## 1. Experimental Overview

**Experiment type.** Single-environment simulation study on one classic control benchmark. It is a case study / feasibility demonstration, not a benchmark evaluation. There is no ablation study, no cross-environment sweep, and no external baseline comparison.

**Scale.**

| Dimension | Count |
|---|---|
| Environments | 1 (`InvertedPendulum-v4`, Gymnasium/MuJoCo) |
| Teacher agents | 1 (TD3, one configuration) |
| Student models | 1 (Decision Tree Regressor, `max_depth=7`) |
| External baselines | 0 |
| Internal ablations | 0 (no with/without-`Pole Urgency` run, no depth sweep, no noise-level sweep) |
| Evaluation episodes | 50 consecutive episodes for the student; "all evaluation episodes" (count unspecified) for the teacher |
| Random seeds | Not reported |
| Result tables | 0 — all quantitative results are in prose or figures |

**Reproducibility signals.**

- Code: **not released**. The text says "Based on the project code" (Sec. III-B) and "the project code" is referenced as ground truth for the architecture, but no repository URL, DOI, or supplementary link appears anywhere in the paper.
- Data: generated by rollout, so it is in principle regenerable — but the generation recipe is under-specified (see §2).
- Hyperparameters: TD3 hyperparameters are partially given (4 items), sourced from CleanRL defaults. Distillation hyperparameters are almost entirely missing (only `max_depth=7`).
- Frameworks named: Python 3.10, PyTorch, scikit-learn, CleanRL, Gymnasium.
- Hardware: "a standard workstation" — no CPU/GPU model, no memory, no wall-clock training time.
- **There is no appendix.** The paper ends at the references after 6 pages. The instruction to include appendix content cannot be satisfied because no appendix, supplementary material, or extended-results section exists. This is itself a reproducibility finding: all implementation detail that would normally live in an appendix (seeds, dataset size, tree hyperparameters, tuning protocol, numerical result tables) is simply absent from the paper.

## 2. Datasets

There is exactly one dataset, and it is self-generated. No public dataset is used.

### 2.1 Distillation dataset (expert rollout buffer)

| Attribute | Reported value | Status |
|---|---|---|

| Feature vector | `(x, v, θ, ω)` plus engineered `P_urgency = θ + K_d · θ̇` | Stated; unclear whether the 4 raw dims are retained alongside the engineered feature or partly replaced |
| Label | Teacher's continuous torque `a ∈ [−3, 3]` | Stated. Ambiguous whether the recorded label is the *clean* teacher action or the *noise-injected* executed action — this materially changes what the student learns |
| Number of transitions | **Not reported** | Missing |
| Number of rollout episodes | **Not reported** | Missing |
| Train/validation/test split | **Not reported** — no held-out split is ever mentioned | Missing |
| Noise injection | Gaussian noise added to expert actions ("Noisy Oracle Rollouts") | Stated; **σ not reported** for the harvesting phase (σ = 0.1 is given only for TD3 *training* exploration) |
| Transient emphasis | Data from "the initial transient states" was "specifically collected and emphasized" to fix the "initial 2-second problem" | Stated qualitatively; **no oversampling ratio, no definition of the transient window, no reweighting scheme** |
| `K_d` value | **Not reported** | Missing — this is the single most important free parameter of the paper's central contribution |

### 2.2 Preprocessing steps (as reconstructable)

1. Load converged TD3 actor.
2. Roll out in `InvertedPendulum-v4`; at each step compute `a_clean = π_T(s)`, then execute `a_exec = a_clean + ε`, `ε ~ N(0, σ²)` (σ unspecified).
3. Record `(s, a)` pairs; oversample or preferentially retain early-episode transitions.
4. Append the engineered feature `P_urgency = θ + K_d·ω`.
5. Fit `DecisionTreeRegressor(max_depth=7)`.

No normalization, standardization, clipping, or de-duplication is mentioned. For a decision tree, scaling is irrelevant (splits are scale-invariant), so its absence is defensible — but the absence of any held-out split is not, since the reported MSE/R² fidelity numbers could be in-sample.

### 2.3 Environment specification check — inconsistency found

The paper states the failure threshold as `|θ| < 0.2095` rad (Sec. III-A) and later as `±0.209` rad (Sec. IV-B). **0.2095 rad = 12° is the `CartPole-v1` threshold, not the `InvertedPendulum-v4` threshold.** Gymnasium's `InvertedPendulum-v4` terminates when `|θ| > 0.2` rad. The stated action bound `[−3, 3]` and the 1,000-step horizon are correct for `InvertedPendulum-v4`. The mixed threshold suggests the description was partly copied from CartPole documentation, and it means the exact termination condition used in the experiments is uncertain.

CleanRL applies `action_scale` and `action_bias` registered as buffers, so the wording is likely a literal reading of the code.

### 3.2 Student: Decision Tree Regressor

| Component | Value |
|---|---|
| Library | scikit-learn `DecisionTreeRegressor` |
| `max_depth` | 7 |
| Split criterion | **Not reported** (default `squared_error`) |
| `min_samples_leaf` / `min_samples_split` | **Not reported** |
| `ccp_alpha` / pruning | **Not reported** |
| `random_state` | **Not reported** |
| Feature set | `(x, v, θ, ω, P_urgency)` — inferred; the paper does not enumerate the final feature vector |
| Resulting leaf count | **Not reported numerically**, despite being defined as an evaluation metric (Sec. III-F(c)) |
| Output type | Piecewise-constant real-valued torque (one constant per leaf) |

The tree is a **regressor**, so the "discrete actions" of the student are not a fixed discrete action set — they are the leaf mean predictions. The paper's framing of "control quantization" into "how many discrete force levels" is therefore correct in effect (≤ 2⁷ = 128 possible outputs) but the actual number is never stated.

### 3.3 Distillation procedure

Critically, the paper spends Sec. II-D deriving the **VIPER / DAgger** objective (Eqs. 1–2), including the `Q`-weighted suboptimality loss under the student-induced distribution `d^{π_S}`. **The methodology then does not implement it.** Sec. III-C describes a single-pass behavioral-cloning harvest with action-space Gaussian noise. There is no dataset aggregation loop, no iteration index `k`, no use of `Q^{π_T}` for loss weighting, and no student-induced state distribution. The noisy-oracle trick is a *state-coverage* heuristic that partially mitigates covariate shift, but it is not the algorithm the related-work section sets up as the solution. This is a substantive gap between stated theory and executed experiment.

### 3.4 Evaluation protocol

- Teacher: average episodic return over an unspecified number of episodes.
- Student: 50 consecutive episodes, 1,000-step horizon, success = no termination.
- Fidelity: MSE and R² between teacher and student actions "across identical offline states" (Fig. 3 caption) — i.e., open-loop, on the offline dataset.
- Stability: histogram of steady-state pole angle; maximum deviation `θ_max`.
- Chattering: rate of sign changes of applied force, compared across **independent closed-loop rollouts** of teacher and student (Fig. 5 caption).
- No confidence intervals, no standard deviations, no significance tests, no seed variance anywhere.

## 4. Baselines

**There are no baselines in the conventional sense.** The only comparison is teacher vs. student. Enumerating what a rigorous version of this study would require, against what is present:

| Candidate baseline | Present? | Why it matters |
|---|---|---|
| TD3 teacher (upper bound) | ✅ Yes | Correctly serves as the performance ceiling and the fidelity reference |
| Decision tree **without** `Pole Urgency` | ❌ No | This is the paper's headline contribution. Without it, the claim that the engineered feature enables depth-7 success is unsupported |
| Decision tree at other depths (3, 5, 9, unlimited) | ❌ No | The claim that depth 7 is "an optimal balance" is asserted, never measured |
| Behavioral cloning **without** noisy rollouts | ❌ No | The claim that noisy oracle rollouts are necessary for recovery behavior is unsupported |
| VIPER (Bastani et al.) | ❌ No | Derived in Sec. II-D as the principled method; never run |
| DTPO (Vos & Verwer 2024) | ❌ No | Cited in Sec. IV-C as prior art achieving NN-level performance with trees; explicitly not compared against |
| Classical PD / LQR controller | ❌ No | The engineered feature is literally a PD term. A hand-tuned PD controller would likely solve `InvertedPendulum-v4` to 1000.0 with *smooth* output, which would undercut the entire pipeline. Its absence is the most consequential omission |
| Linear policy / logistic regression surrogate | ❌ No | Would test whether tree structure is needed at all |

**Comparison fairness.** The teacher–student comparison itself is fair on the task-performance axis (same environment, same horizon, both at ceiling). The **chattering comparison in Fig. 5 is not a controlled comparison**: the caption states the two trajectories come from *independent* closed-loop rollouts, meaning the teacher and student are visiting different state sequences. A controlled version would replay identical states through both controllers, or report chattering statistics aggregated over many matched-seed episodes. As presented, the chattering gap is qualitatively unsurprising (piecewise-constant vs. smooth output) but not quantified — **no numerical switching frequency is reported anywhere**, despite chattering being a defined evaluation metric.

## 5. Experimental Process, Step by Step

Reconstructed from Sec. III–IV. Steps marked **[U]** are underspecified; steps marked **[I]** contain an inconsistency.

**Phase A — Environment setup**
1. Instantiate `InvertedPendulum-v4` from Gymnasium (MuJoCo backend), 4-D observation, 1-D continuous torque in `[−3, 3]`, `+1` reward per surviving step, 1,000-step cap.
2. Fix the failure threshold. **[I]** Paper states 0.2095 / 0.209 rad; the actual env uses 0.2 rad.

**Phase B — Teacher training**
3. Configure CleanRL TD3: actor `4 → 256 → 256 → 1` with ReLU + Tanh, twin critics (assumed default), Adam at 3 × 10⁻⁴, batch 256, exploration σ = 0.1.
4. Train until convergence. **[U]** Total timesteps, buffer size, γ, τ, policy-delay, learning-starts, and seed count are all unreported; no learning curve figure is provided.
5. Verify convergence: teacher returns 1000.0. **[U]** Number of evaluation episodes unstated; no variance given (though at a hard ceiling of 1000.0 the variance is necessarily zero if all episodes succeed).

**Phase C — Dataset harvesting (Noisy Oracle Rollouts)**
6. Freeze the actor.
7. Roll out episodes; at each step compute the deterministic teacher action and perturb it with Gaussian noise before execution. **[U]** Harvest-time σ unreported. **[U]** Whether the stored label is the clean or perturbed action is unreported.
8. Preferentially collect/emphasize early-episode transitions to address the "initial 2-second problem." **[U]** No window definition (2 s ≈ 40 steps at the env's 0.05 s `dt`? unstated), no oversampling factor, no sample weights.
9. Terminate harvesting. **[U]** Dataset size unreported.

**Phase D — Feature engineering**
10. Compute `P_urgency = θ + K_d · θ̇` per sample. **[U]** `K_d` value unreported; no tuning procedure for `K_d` described.
11. Assemble the design matrix. **[U]** Final feature list not enumerated.

**Phase E — Student fitting**
12. Fit `DecisionTreeRegressor(max_depth=7)` on the harvested pairs. **[U]** No train/val/test split described; no cross-validation; all sklearn hyperparameters other than depth left at unstated defaults.
13. Monitor behavioral fidelity (MSE, R²) during distillation, but treat **closed-loop success rate over 50 episodes** as the primary selection metric (Sec. III-E). This is methodologically the right choice — offline fidelity is a poor proxy for closed-loop competence — but it means model selection was performed on the same 50-episode protocol later reported as the result, i.e. **the reported 100% success rate is a selection-set number, not a held-out number**.

**Phase F — Evaluation**
14. Run 50 consecutive closed-loop episodes with the tree in the loop; count episodes reaching 1,000 steps → 100%.
15. Produce the teacher-vs-student action scatter over identical offline states (Fig. 3); observe horizontal banding = leaf-level quantization.
16. Histogram steady-state pole angle over the trajectories (Fig. 4); observe a bimodal distribution.
17. Plot torque vs. time for teacher and student from independent rollouts (Fig. 5); observe bang-bang chatter in the student.
18. Sweep a 2-D slice of state space at `x = 0, v = 0` and color by predicted action to produce the global decision-boundary map (Fig. 6). **[U]** Grid resolution and action-to-color binning unreported.
19. Build a live dashboard rendering the simulation alongside the active root-to-leaf IF-THEN path, the urgency value, and a limit-cycle monitor (Fig. 7).

**Phase G — Ablation / sensitivity**
20. **Not performed.**

### 6.1 Primary metrics and definitions

| Metric | Definition (as given) |
|---|---|
| Closed-Loop Success Rate | % of test episodes surviving the full 1,000 steps without threshold violation |
| Average Episodic Return | Mean cumulative reward over 50 consecutive episodes |

| Quantity | Teacher (TD3) | Student (DT, depth 7) |
|---|---|---|
| Average episodic return | **1000.0** ("consistent … across all evaluation episodes") | not stated numerically; implied 1000.0 via 100% success |
| Closed-loop success rate | implied 100% | **100%** over **50** episodes, 1,000-step horizon |
| Action MSE | — | **not reported** |

| Failure threshold | — | stated as **±0.209 rad** |

### 6.3 Critical numerical inconsistency

Sec. IV-B states, in consecutive sentences, that the pole "safely oscillates between two boundaries (≈ ±0.5 rad)" and that "the maximum deviation remains strictly within the failure thresholds (±0.209 rad)." **These are mutually contradictory: 0.5 > 0.209.** If the limit cycle genuinely reached ±0.5 rad, the environment would have terminated the episode and the 100% success rate would be impossible.

Possible resolutions, none of which the paper disambiguates:
- The ±0.5 figure refers to a different quantity (angular *velocity* ω in rad/s, or cart position `x` in metres) and was mislabeled as pole angle.
- The bimodal peaks are at ≈ ±0.05 rad and a decimal point was dropped.
- The histogram x-axis in Fig. 4 is in different units than the prose claims.

Because this is the paper's central stability claim — the empirical evidence for BIBO stability — the inconsistency invalidates the quantitative form of the claim as written. The qualitative claim (bounded oscillation rather than divergence) is still supported by the 100% success rate, since surviving 1,000 steps *implies* `|θ|` never exceeded the threshold. So the conclusion is likely right and the reported number is likely wrong, but a reader cannot verify which.

### 6.4 Performance patterns

**Where the approach works.**
- Task-level parity: the depth-7 tree matches the teacher's ceiling performance (1000.0 / 100%) on this benchmark. This is the paper's strongest empirical claim and it is internally consistent.
- Recovery behavior: qualitatively, the noisy-oracle data is credited with letting the tree handle the early-episode transient. No before/after measurement supports this.
- Global structure: Fig. 6 shows diagonal switching boundaries in the (θ, ω) plane at `x = 0, v = 0`, which is the expected geometric signature of an axis-aligned tree operating on a linear combination feature. The analogy drawn to Sliding Mode Control switching surfaces is apt and is the most technically interesting observation in the paper.

**Where it struggles.**
- Actuation smoothness: piecewise-constant output produces high-frequency sign flips (Fig. 5). Acknowledged as the main limitation.
- Steady-state precision: the tree cannot hold `θ = 0`; it necessarily settles into a limit cycle around the equilibrium, since no leaf outputs the exact stabilizing torque as a continuous function of state.
- Fidelity vs. competence divergence: quantization means MSE is bounded away from zero by construction (the paper says as much — "MSE establishes the lower bound of approximation error"), yet closed-loop performance is unaffected. This is a genuine and useful finding about metric choice, but it is stated rather than measured.

### 6.5 Statistical significance

None reported. No standard deviations, no confidence intervals, no seed-level variance, no hypothesis tests. With both systems saturating the reward ceiling, a significance test on return is uninformative; but 100% over 50 episodes yields only a 95% Clopper–Pearson lower bound of roughly 0.93, which is worth stating for a safety-critical framing. Chattering and `θ_max` are the metrics where variance actually matters, and neither has any dispersion estimate.

**None.** The paper makes three causal claims about design choices, and provides zero controlled evidence for any of them:

| Claim | Section | Evidence provided |
|---|---|---|
| `Pole Urgency` enables a shallower tree ("significantly shallower … max depth = 7") | III-C, V-A | None. No depth-vs-performance curve with and without the feature |

| Depth 7 is "an optimal balance between model complexity and human readability" | III-E | None. No depth sweep |

The comparative word "significantly shallower" has no referent — no deeper baseline tree was ever trained.

### 7.2 Sensitivity analysis

**None.** No sensitivity to `K_d` (whose value is not even disclosed), harvest noise σ, dataset size, tree depth, or `min_samples_leaf`. For a paper whose contribution is a single engineered feature parameterized by one gain, the absence of a `K_d` sweep is the largest analytical gap.

### 7.3 Qualitative analysis and visualizations

Five figures, all qualitative, none with numerical annotations:

- **Fig. 1** — environment screenshot.
- **Fig. 2** — "simplified top-level structure" of the tree. Simplified, so the full auditable rule set (the paper's core interpretability deliverable) is never actually shown. For a paper arguing human-readable IF-THEN control, publishing the complete depth-7 rule set (or at least the top 3–4 levels with thresholds and leaf torques) should have been mandatory.

## 9. Review

### 9.1 Experimental Strengths

- **Correct primary metric.** Selecting on closed-loop success rate rather than offline imitation MSE is the methodologically right call, and the paper explains why (quantization floors the MSE without harming control).
- **Control-theoretic evaluation axes.** Bringing limit-cycle structure, quantization rate, BIBO boundedness, and chattering frequency into the evaluation of a distilled policy is a real contribution to how XRL surrogates should be validated. Most policy-distillation papers report return and tree size only.
- **Physics-aware feature is well-motivated.** The diagnosis is precise and correct: axis-aligned trees cannot express diagonal boundaries in (θ, ω), and injecting a PD-style linear combination gives one split the expressive power of many. The Sliding Mode Control analogy is a good framing.
- **Noisy Oracle Rollouts as a cheap covariate-shift mitigation.** Perturbing the expert to expose near-failure states is a sensible, low-cost alternative to a full DAgger loop for a low-dimensional system.
- **Both global and local interpretability delivered.** The decision-boundary map plus the live decision-path dashboard cover complementary explanation needs, and the live-path tool is deployment-relevant rather than purely post-hoc.
- **Honest about the core drawback.** The bang-bang/chatter limitation is stated plainly in the Discussion and Conclusion rather than buried.

### 9.2 Experimental Limitations

**Scope and generalization.**
1. Single 4-D environment with a scalar action, ceiling-saturating reward, and no stochasticity. `InvertedPendulum-v4` is solvable by a hand-tuned PD controller, so 100% success demonstrates task feasibility, not the value of the pipeline. The claims in Sec. V-C about autonomous driving safety layers and robotic locomotion are extrapolations with no supporting experiment.
2. Reward saturation destroys measurement resolution. When teacher and student both hit exactly 1000.0, return cannot distinguish a good distillation from a barely-adequate one. The interesting differences are pushed entirely into un-quantified metrics (chatter, `θ_max`), which are then not reported numerically.

**Missing baselines and ablations.**
3. Zero baselines. No PD/LQR reference, no tree without `Pole Urgency`, no clean-data behavioral cloning, no VIPER, no DTPO. Every causal claim in the paper is therefore uncontrolled.
4. The derived method is not the implemented method. Eqs. 1–2 set up `Q`-weighted DAgger; the experiments run single-pass noisy behavioral cloning. The paper never acknowledges this substitution or discusses what is lost.

**Metrics and reporting.**
5. Half the declared metrics are never instantiated. MSE, R², leaf-node count, and chattering frequency are all formally defined in Sec. III-F and then appear only as adjectives ("strong correlation", "high-frequency"). For a paper whose Conclusion claims a "rigorous framework for validating surrogate models", not reporting the framework's own numbers is a serious internal failure.
6. No results table, no seeds, no variance, no confidence intervals. `n = 50` with a 100% point estimate should carry an interval.
7. Model selection and evaluation share the same 50-episode protocol (Sec. III-E vs. Sec. IV-B), so the headline 100% is optimistic by construction. There is no held-out episode set and no evidence of a train/test split on the distillation data either, meaning the (unreported) fidelity figures may be in-sample.

**Internal consistency.**
8. **±0.5 rad limit cycle vs. ±0.209 rad failure threshold is a direct contradiction** (§6.3) that undermines the BIBO claim as stated.
9. **Failure threshold value is wrong for the stated environment** — 0.2095 rad is CartPole's, `InvertedPendulum-v4` uses 0.2 rad (§2.3).
10. Fig. 5's chatter comparison uses independent rollouts, so it compares two different state trajectories and cannot isolate the controller's contribution.
11. Fig. 2 shows only a "simplified top-level structure," so the interpretability artifact the paper exists to produce is never fully published.
12. Citation indices for VIPER and Tabrez & Hayes are swapped/broken; Bastani et al. [12] is never cited in text (§8.1).

**Undisclosed parameters that block replication.**
13. `K_d` — the single parameter defining the paper's headline feature — is never given.
14. Harvest-time noise σ, dataset size, transient-oversampling ratio, and all TD3 training-length parameters are absent.

**Interpretability claims are unevaluated.**
15. "Human-readable", "exceptional human readability", and "verifiable" are asserted without any human-subject study, expert audit, formal verification run, or even a rule-count-vs-comprehension proxy. Depth 7 permits up to 128 leaves and 127 internal thresholds; whether that is genuinely auditable is an empirical question the paper does not test. Notably, VIPER's original selling point was *formal verification*, which this paper mentions but never performs.

### 9.3 Reproducibility Assessment

**Overall score: Low.**

Reasoning: the environment is public and standard, and the teacher-side setup can be approximately recovered from CleanRL defaults, which is the one point in favor. But the distillation side — the actual contribution — is missing its defining hyperparameter (`K_d`), its dataset specification (size, split, noise level, oversampling scheme), and its numerical results (four of eight metrics). No code is released. No seeds are reported. Two reported numbers are mutually contradictory. An independent team could build *a* physics-aware tree-distillation pipeline for the inverted pendulum and would probably also reach 100% success — because the task is easy — but they could not reproduce this paper's specific model, verify its fidelity figures, or check its stability numbers.

**Key gaps, ranked by blocking severity.**

1. `K_d` value for `P_urgency` — blocks reproduction of the central contribution.
2. No code release.
3. Dataset spec: number of transitions, number of episodes, harvest σ, transient-window definition and oversampling ratio, clean-vs-noisy labeling choice, train/test split.
4. Unreported metric values: action MSE, action R², leaf count, chattering frequency.
5. TD3 training length, γ, τ, policy delay, target-noise, buffer size, seeds.
6. Unresolved ±0.5 vs. ±0.209 rad contradiction and the 0.2095 vs. 0.2 rad threshold error.
7. sklearn tree parameters beyond `max_depth`; `random_state`.
8. Full decision tree structure (thresholds and leaf torques).

### 3.2 Validity-check protocol (differential testing)

Motivation: in CARLA a 66-D configuration's feasibility depends on many implicit constraints, so per-input feasibility verification is impractical. Invalid inputs would inflate crash counts and distort robustness estimates.

Protocol: for each agent under test, an *independently trained, highly robust validation policy* is run on the same generated input. The input is counted as valid **only if the validation policy completes the task while the target agent fails** `[38]`. The crash is then attributed to the target policy rather than to an infeasible configuration.

| Environment | Validation policy | Its failure rate under random testing |
|---|---|---|
| MountainCar | PPO | 0% |
| BipedalWalker | SAC | 0% |
| CARLA | CaRL | 2.5% |

The authors acknowledge CaRL's higher rate and justify it as the most robust CARLA policy available to them.

This is a strong methodological contribution — most of the benchmarked primary papers do not filter for input feasibility at all, and unfiltered crash counts are a known source of inflated results. But the operator is a *conservative filter with asymmetric error*, and its consequences deserve emphasis:

- It is **not** a validity test; it is a *relative-difficulty* test. Any input on which both policies fail is discarded, including inputs that are perfectly feasible and expose a real target-agent defect that the validation policy happens to share. The hardest, arguably most valuable crashes are systematically the ones most likely to be filtered out.
- Consequently **#UC is a function of the validation policy**, not solely of the fuzzer. On CARLA, with CaRL at 2.5% random failure, the filter's own false-negative rate is nontrivial and rises on adversarially-mutated (i.e., harder-than-random) inputs — exactly where fuzzers concentrate. The filter's rejection rate is therefore correlated with fuzzer aggressiveness, which is a differential bias, not merely a constant offset.
- Fuzzers that push into genuinely hard regions of the input space (plausibly QDFuzz and SeqDivFuzz, by design) are penalized relative to fuzzers that find "easy" crashes near the nominal distribution. This could interact with the headline RQ1 finding.
- Nothing in the excerpt reports **how many** generated inputs were rejected per method per environment. Those rejection rates are essential to interpret #UC and would be the first thing I would look for in Section IV/appendix.

## 9. Review

### Experimental Strengths
- Addresses a real and well-articulated gap: inconsistent baselines, non-uniform settings, and missing random-testing lower bounds across the RL fuzzing literature.
- Uses the *corrected* MDPFuzz implementation, explicitly acknowledging the `[36]` vs `[34]` discrepancy as a confound in prior comparisons.
- Includes Random Testing as a first-class baseline and reports that it beats several published methods — a finding the community needs and that authors are often disinclined to publish.
- Deliberate selection of *robust* agents-under-test via a 1,000-configuration failure-rate screen, avoiding ceiling/floor effects.
- Differential-testing validity filter is a real methodological advance over unfiltered crash counting.
- Complexity gradient across benchmarks (2-D → 15-D → 66-D; 134k → 690k → 1.5M parameters) with distinct RL algorithms (DQN, TQC, PPO) supports claims about scaling behavior.
- Downstream utility evaluation, including **regression-fault measurement** after repair, goes beyond the crash-count-only norm.
- Documented, reasoned exclusion criteria for omitted methods.
- Public artifact release claimed.

### Experimental Limitations
1. **#UC uniqueness criterion is likely too permissive.** A disjunctive seed-or-trajectory criterion with no distance threshold conflates crash *runs* with crash *defects*. This directly and favorably biases high-throughput methods, i.e., it may be partly generating the RQ1 conclusion rather than measuring it. (Definition truncated; flagged as the top item to verify.)
2. **Validity filter has fuzzer-correlated bias.** The filter discards every input on which the validation policy also fails. Since aggressive fuzzers concentrate on harder inputs, their rejection rate should be higher, biasing #UC against exploration-oriented methods. Compounded on CARLA where the validation policy itself fails 2.5% of the time under merely random inputs. Per-method rejection rates are not reported in the excerpt.
3. **MountainCar's search space is collapsed to one dimension.** Freezing velocity leaves a 1-D scalar input space against 10,000 seeds. Under those conditions Random Testing is close to exhaustive, so "random testing is competitive on simple tasks" is close to a design artifact of the benchmark rather than a finding about task simplicity. The conclusion should be scoped accordingly.
4. **Budget normalization undefined in the available text.** With throughput identified as the causal explanation for MDPFuzz's win and iteration-efficiency as RQ3's metric, the choice of budget unit (wall-clock vs. iterations vs. environment steps vs. episodes) determines the rankings. # Experimental Analysis: "What do Reward Models Memorize?"

**Paper:** Verhoeven, Mishra, Shutova — *What do Reward Models Memorize?* (arXiv 2607.24484v1, listed 27 Jul 2026)
**Code:** https://github.com/ioverho/rm-shortcuts (advertised in abstract)
**Analysis basis:** Pages 1–8 of main text. Appendices A–H referenced but not available.

## 1. Experimental Overview

**Experiment type.** This is an *analysis/measurement* paper, not a method paper. There is no proposed model to beat baselines with. The empirical work has three layers:

1. **Measurement layer** — train an ensemble of reward models with structured data hold-out to estimate counterfactual memorization (CM) per preference pair, producing "memorization maps".
2. **Hypothesis-driven explanation layer** — annotate 84 hand-designed response features + dataset metadata, fit a surrogate MLP regressor from feature *differences* to TM/TG/CM, and attribute with SHAP.
3. **Data-driven explanation layer** — train a Matryoshka Batch Top-k SAE on preference-pair embedding differences with an auxiliary CM-region classification head, then auto-label latents with an LLM.

**Scale (from main text).**

| Quantity | Value |
|---|---|
| Datasets | 2 (PRISM, COMMUNITY) |
| RMs trained for CM estimation | 25 per dataset → 50 total (plus preceding LM/SFT stages) |
| Preference pairs analyzed | 57.9×10³ (PRISM) + 137×10³ (COMMUNITY) ≈ 195×10³ |
| Annotated features per response | 84 (+ metadata: 77/28 user, 10/0 conversation, 1/0 turn, 3/0 response) |
| Surrogate regressions | 3 endogenous variables × 2 datasets = 6 |
| SAE runs | ≥1 per dataset; 32 latents max, ~4 active |
| Baseline models compared | 0 (no competing RM or memorization method run) |

**Reproducibility signals.** Public code repo; both datasets are public (PRISM, COMMUNITY); backbone is an open checkpoint (Llama-3.2-1B); the paper explicitly points to appendices for "full training methodology" (D) and "full splitting procedure" (B). Against this: **no hardware, wall-clock time, compute budget, seed count, LoRA rank/α/target modules, learning rate, batch size, or epoch count appears anywhere in the main text.** The only stated resource constraint is qualitative — "We use LoRA to enable RM training within our budget."

## 2. Datasets

### PRISM (Kirk et al., 2024)

- **Source/domain:** multi-turn conversations between real users and chat models; turn-level preference labels supplied by the same user who wrote the prompt.
- **Size:** 1.40×10³ users, 8.00×10³ conversations, 27.2×10³ turns, 57.9×10³ preference pairs.
- **Response structure:** turn 1 receives on average **3.75** responses drawn from **21 different models**; subsequent turns receive **2** responses from the **same** model. This asymmetry is load-bearing for the paper's headline "model identity" finding — model-identity contrasts exist essentially only at turn 1.
- **Metadata:** 77 user-level, 10 conversation-level, 1 turn-level, 3 response-level fields.
- **Preprocessing:** conversational history is prefixed into the prompt `x`. Only pairwise preferences **without ties** are used (one `y+`, one `y−`). Full detail deferred to Appendix A (unavailable).
- **Usage:** primary dataset; richer metadata and multi-model responses make it the site of the model-identity and rule-based-reward analyses.

### COMMUNITY (Zhang et al., 2025a)

- **Subset used:** the "balanced, English-only" subset.
- **Size:** 0.77×10³ users, 17.8×10³ conversations, 45.8×10³ turns, 137×10³ preference pairs.
- **Response structure:** every turn receives **4** responses from the **same** model. Consequently there is no model-identity contrast at all, and the paper notes response differences are "more subtle".
- **Metadata:** 28 user-level fields only; 0 conversation-, turn-, and response-level.
- **Usage:** control/replication dataset. Critically, it is the dataset where the user-preference-margin effect can be observed *without* the margin having been injected into the loss (see §4), which is what upgrades that finding from artifact to phenomenon.
- **Known recruitment structure:** users in the "(At most) Complete Secondary" education group come "almost entirely from a second recruitment wave" (Appendix F Table 6, unavailable) designed to raise the share of less-educated participants. This is exploited as a natural probe for shortcut memorization.

### Numerical consistency check on pair counts

- PRISM: 57.9k pairs / 27.2k turns ≈ 2.13 pairs per turn. Consistent with a mixture of turn-1 turns (3.75 responses → up to C(3.75,2)≈5 pairs) and later turns (2 responses → 1 pair). Internally coherent.
- COMMUNITY: 4 responses per turn implies C(4,2)=6 pairs per turn, so 45.8k × 6 = **274.8k** possible pairs, yet **137k** are reported — almost exactly half. The paper never explains this factor of ~2. Plausible causes: ties dropped, only a partial ranking available, or a deduplication/subsampling step. **This is an unexplained discrepancy in the main text**; presumably resolved in Appendix A, which is unavailable.

## 3. Experimental Setup (Detailed)

### RM training pipeline

- **Backbone:** Llama-3.2-1B (Llama3Team, 2024). Configuration deferred to Appendix C.
- **Pipeline:** standard three-stage `LM → SFT → RM` (Ziegler et al., 2019; Wang et al., 2024a), described as standard for discriminative RMs (Zhong et al., 2025). The SFT stage's data source is **not specified in the main text** — an important gap, since SFT data determines what the RM has already seen before CM measurement begins.
- **Objective:** Bradley–Terry likelihood, `p(y+ ≻ y−) = σ(rm(y+|x) − rm(y−|x))` (Eq. 1).
- **Margin term:** for PRISM, the **user preference margin is included in the RM training objective** (stated in §4, referring to Appendix D). Not stated for COMMUNITY, where the margin is described as "implicit and granular".
- **PEFT:** LoRA (Hu et al., 2021), motivated by budget. Rank, α, dropout, target modules, and whether the value/reward head is fully trained are all unreported in the main text. Appendix D reportedly discusses "the interaction of PEFT with memorization" — this discussion is essential to the paper's validity and cannot be evaluated here.
- **Unreported:** optimizer, LR and schedule, batch size, epochs, sequence length/truncation, precision, hardware, per-run and total training time, number of seeds beyond the 25 data subsets.

### Memorization estimation protocol

- **Metric (Eq. 2):** `CM = E[p(y+≻y−) | pair ∈ D_train] − E[p(y+≻y−) | pair ∉ D_train]`, i.e. `TM − TG`. Note the estimand is the **BT probability of correct classification**, not accuracy or a logit margin.
- **Ensemble design:** 25 randomly sampled subsets of the same data; each preference pair appears in exactly **20** subsets (contributing to TM) and is held out in the remaining **5** (contributing to TG).
- **Splitting granularity:** **user-level**, explicitly to avoid user preference leakage; Appendix B additionally covers "mitigating user–user confounding". So each RM sees roughly 80% of users.
- **Estimator variance:** TM averages 20 measurements per pair; TG averages only **5**. The asymmetry is a design weakness the paper implicitly acknowledges when it attributes the small population of negative-CM pairs near (1,1) to "noise".

### Hypothesis-driven feature set (84 per response)

| Block | # features | What it measures |
|---|---|---|
| Anthropomorphism (AnthroScore) | 1 | extent LLM treats itself as human |
| Complexity | 9 | length, diversity, complexity |
| Dialog acts | 23 | presence of a specific dialog act |
| Emotion | 28 | dominant emotion + sentiment |
| Politeness | 4 | (im)politeness |
| Rule-based rewards | 16 | presence of particular LLM behaviors |
| Sycophancy | 3 | support for user framing |
| **Total** | **84** | |

Plus author-provided metadata blocks: User, Conversation, Turn, Response, and User Margin. Annotation uses "a combination of task-specific and general-purpose LLMs" (Appendix E, unavailable) — **model names, prompts, temperature, and any human-agreement validation are not in the main text.**

**Pairing convention:** each feature becomes a *difference* between chosen and rejected response; positive difference = feature more prevalent in the chosen response.

### Surrogate regression + attribution

- **Regressor:** 3-layer MLP; input = full feature-difference vector; output = one of TM / TG / CM. Hidden widths, activation, optimizer, regularization, and early-stopping criterion are unreported.
- **Split:** 20% of all preference pairs held out for evaluation. No validation split is mentioned, so it is unclear whether regressor hyperparameters were tuned, and if so on what.
- **Attribution:** SHAP (Lundberg and Lee, 2017), **conditional** Shapley values. **1×10³ preference pairs reserved as the perturbation/background set**; explanations computed on "all remaining samples".
- **Aggregation to block level:** two summary metrics, defined fully in Appendix F:
  - **MAV** — mean absolute value of the block *net* SHAP value; higher = more important in absolute terms.
  - **HMR** — harmonic mean rank of block net SHAP across a row, i.e. inverse MRR; lower = more important relative to other active features for the same pair.

### SAE (data-driven features)

- Reimplementation of Movva et al. (2025) RM-SAEs.
- **Input:** embedding difference `f(x,y+) − f(x,y−)`, where `f` is the same LM used to initialize the RMs.
- **Architecture:** Matryoshka Batch Top-k SAE (Bussmann et al., 2024, 2025); **max 32 latents, average 4 active per sample**.
- **Loss:** L2 reconstruction + **auxiliary CM-region classification loss** on the sparse latents. The region head is effectively a logistic regression; its weights are read as region↔feature associations.
- **Regions:** the memorization map is partitioned into **4 disjoint regions** — low/low, medium/medium, high/low, high/high in (TM, TG). **The numeric thresholds defining these regions are never given in the main text**, and Figure 1 is referenced for them rather than a table. This is a material reproducibility gap.
- **Latent labeling:** high-scoring pairs fed to **OpenAI gpt-5** for descriptions; descriptions validated by annotating a data subset with **OpenAI gpt-5-mini** and correlating against the SAE's active latent; only descriptions maximally correlated with active dimensions and **significant at 0.05 after Bonferroni correction** are retained.

### Evaluation protocol

- **Primary quantities:** TM, TG, CM per pair (not model-level accuracy).
- **Regressor fit quality:** R² on the held-out 20%.
- **Attribution quality:** MAV/HMR summaries; per-feature SHAP correlations (Appendix H Tables 8–9).
- **Notably absent:** any conventional RM quality evaluation. No accuracy on a held-out preference test set, no RewardBench-style benchmark, no comparison against published RM baselines. We therefore cannot judge whether these RMs are competent enough for their memorization patterns to generalize to production-scale RMs.

## 4. Baselines

There are **no experimental baselines** in the usual sense. This is a legitimate consequence of the paper's goal, but it constrains what can be concluded. The relevant comparison structure is instead internal:

| Comparison axis | Role | Fairness assessment |
|---|---|---|
| PRISM vs COMMUNITY | Cross-dataset replication | Reasonable but asymmetric: PRISM has 21 response models and 91 metadata fields; COMMUNITY has 1 model and 28 fields. Several PRISM findings (Model, Conversation blocks) are structurally impossible to test in COMMUNITY. Not a clean replication. |
| TM vs TG for the same feature | The core contrast defining memorization vs overgeneralization | Sound in principle; the interpretive rule is stated clearly (large positive CM SHAP = memorization; large negative = overgeneralization). Weakened by the 20-vs-5 estimator asymmetry. |
| Hypothesis-driven features vs SAE features | Convergent validation of the same claims from two directions | Genuine methodological strength — the SAE independently recovers the length/brevity story. |
| Prior dataset-map work (Singhal et al., 2024; Lee et al., 2025) | Discussed in §2 | **Discussed, not run.** The paper distinguishes itself from these methods but never empirically compares its map against theirs, so the added value of counterfactual memorization over cheaper training-dynamics maps is asserted rather than demonstrated. |
| Alternative memorization estimators | — | None. No comparison to influence functions, memorization-via-canaries, or leave-one-out. |
| Alternative backbones/scales | — | None. Single 1B model, single PEFT regime. |

## 5. Experimental Process (Step-by-Step)

Reconstructed from the main text; steps marked ⚠ depend on unavailable appendix detail.

**Stage A — Data preparation**
1. Load PRISM and the balanced English-only subset of COMMUNITY.
2. Flatten multi-turn conversations into `(x, y)` items, prefixing conversational history into the prompt. ⚠ (Appendix A: exact template, truncation.)
3. Convert per-turn ranked response lists into pairwise `(y+, y−)` preferences, dropping ties. ⚠ (COMMUNITY yields 137k rather than the combinatorial 274.8k — filtering rule unstated.)
4. Compute per-pair user preference margins (explicit in PRISM, implicit/granular in COMMUNITY).
5. Attach all available metadata at user/conversation/turn/response level.

**Stage B — Cross-fitting design for counterfactual memorization**
6. Partition **users** (not pairs) into 25 overlapping subsets such that each preference pair lands in the training set of exactly 20 subsets and is held out from 5. ⚠ (Appendix B: exact construction; user–user confounding mitigation — presumably grouping users who share prompts/conversations.)

**Stage C — RM training (×25 per dataset)**
7. Start from Llama-3.2-1B. ⚠ (Appendix C.)
8. Run the LM → SFT stage. ⚠ (SFT corpus unspecified in main text — a real gap, since SFT exposure precedes and could contaminate the "unseen" condition.)
9. Attach a scalar reward head and train with the Bradley–Terry loss (Eq. 1), adding the margin term for PRISM. ⚠ (Appendix D: LoRA config, LR, batch size, epochs.)
10. Repeat for all 25 subsets, per dataset → 50 RMs.

**Stage D — Metric computation**
11. For each preference pair, evaluate `p(y+≻y−)` under all 25 RMs.
12. Average over the 20 RMs that trained on it → **TM**; average over the 5 that did not → **TG**; take the difference → **CM**.
13. Plot the joint (TM, TG) histogram plus per-CM-bin marginal KDEs → **memorization maps** (Figure 2). CM bins used: `<0.0, 0.0–0.2, 0.2–0.4, 0.4–0.6, 0.6–0.8, 0.8–1.0`. The increasing-CM direction is the perpendicular to the `TM = TG` diagonal, maximal at (1, 0).

**Stage E — Hypothesis-driven attribution**
14. Annotate all responses with the 84 features using task-specific + general-purpose LLMs. ⚠ (Appendix E.)
15. Convert to per-pair chosen-minus-rejected differences.
16. Fit the 3-layer MLP separately for each of TM, TG, CM, on each dataset (6 fits), holding out 20% of pairs.
17. Report held-out R².
18. Compute conditional SHAP values using a 1k-pair perturbation set, explaining all remaining pairs.
19. Aggregate to block-level MAV and HMR (Appendix F Tables 4–5 → Figure 3) and to feature-level statistics (Appendix H Tables 8–9).
20. Run targeted partial-effect analyses:
    - **Model identity** (Figure 4): mean SHAP when a given model is chosen / rejected / used for both responses, models sorted by average RM score; correlation of RM model preference with human preference in Appendix F Figure 12.
    - **Rule-based rewards & sycophancy** (Figure 5): the flip statistic `E[SHAP | feat(y+)=1, feat(y−)=0] − E[SHAP | feat(y+)=0, feat(y−)=1]`, with HMR on a secondary axis conditioned on a feature difference being present.
    - **Complexity/length direction split** (Appendix H Figure 13): SHAP sign when chosen is more vs less complex than rejected.

**Stage F — Data-driven attribution**
21. Partition the memorization map into the 4 regions.
22. Embed each pair as `f(x,y+) − f(x,y−)` with the RM-initialization LM.
23. Train the Matryoshka Batch Top-k SAE (≤32 latents, ~4 active) on L2 reconstruction + region-classification loss.
24. Read region-classifier weights as region↔latent associations.
25. Label latents with gpt-5 from high-scoring pairs; validate via gpt-5-mini annotation and correlation; keep only Bonferroni-significant (α=0.05) maximally-correlated descriptions (Appendix G Table 7 → Figure 6).

**Hyperparameter tuning process:** never described. There is no statement of any search over RM, MLP, or SAE hyperparameters, no validation split for the regressor, and no sensitivity analysis over the 25/20/5 ensemble design, the 32-latent SAE budget, or the 4-region thresholds. This is the largest methodological hole in the reported process.

## 6. Results

### Primary quantities

- **TM** — expected BT probability of correct preference classification when the pair was in training.
- **TG** — same, when held out.
- **CM = TM − TG** — graded per-instance memorization.
- **MAV / HMR** — absolute and relative block-level SHAP importance.
- **R²** — held-out fit of the surrogate regressor.

### Memorization maps (Figure 2)

- The overwhelming majority of pairs lie **below the TM=TG diagonal** (better classified after inclusion in training) — the expected direction.
- **Most pairs are already memorized**: mass concentrates on the right side of the map (high TM).
- **Most pairs also have high TG**, producing a dense cluster near **(1, 1)**. High-CM pairs are therefore **rare**.
- **Negative-CM pairs** also cluster near (1,1) and are attributed to estimator noise.
- No quantitative summary of the CM distribution (mean, median, quantiles, fraction above thresholds) is given in the main text — only the visual. This makes the qualitative claims hard to check.

### Surrogate regression fit (PRISM / COMMUNITY)

| Target | PRISM R² | COMMUNITY R² |
|---|---|---|
| TM | 0.56 | 0.63 |
| TG | 0.52 | 0.38 |
| CM | 0.39 | 0.33 |

The authors interpret this as RM performance being "largely, and in some cases mostly, explained by a relatively small set of features," and explain the lower CM R² via footnote 2: features equally important to TM and TG cancel out and have no explanatory power for CM. That explanation is coherent, but note that R²=0.33–0.39 leaves 61–67% of CM variance unexplained, and all subsequent SHAP claims are attributions of *this* surrogate, not of the RM itself.

### Block-level importance ordering (Figure 3, ordered by CM MAV, ascending)

**PRISM:** AnthroScore < Politeness < Sycophancy < Conversation < User < Dialog Acts < Emotions < Rule-based Rewards < Complexity < User Margin < **Model** (highest).

**COMMUNITY:** AnthroScore < Sycophancy < Rule-based Rewards < Politeness < Dialog Acts < Complexity < Emotions < User < **User Margin** (highest).

Cross-dataset agreement: AnthroScore and Sycophancy are consistently least important; Complexity and User Margin consistently near the top. Divergence: Rule-based Rewards is 4th-highest in PRISM but 3rd-*lowest* in COMMUNITY (the authors attribute this to feature rarity, footnote 3); User jumps from mid-pack in PRISM to 2nd-highest CM MAV in COMMUNITY.

### Finding 1 — Misallocated memorization to easy, high-margin pairs

User-preference-margin features are dominant predictors of **TM** in both datasets but substantially worse predictors of **TG**, giving high CM. SHAP correlations (Appendix H) show a strongly positive TM↔margin relationship: larger margin → better in-training performance. Interpretation: the RM learns to identify easy training examples and maximizes its reward margin on them, but cannot recognize the same easy cases when held out. The authors call this a misallocation of memorization capacity.

**Confound handling:** for PRISM the margin was in the training objective, so the effect is partly by construction. The authors correctly note it replicates in COMMUNITY, where the margin is only implicit — this is the strongest piece of confound control in the paper.

### Finding 2 — Dataset-specific shortcut memorization

**Model identity (PRISM only, Figure 4).** RMs show strong preference for particular response models; this preference is *positively correlated with human preference* (Appendix F Figure 12), so it is a genuinely useful-but-spurious signal. High TG SHAP indicates heavy reliance on generator idiosyncrasies. Degradation when a "better" model is rejected (or vice versa) is **moderate when seen in training** and **substantial when unseen — especially for the least-preferred models**, hence high CM. When model identity is uninformative (same model for both responses, i.e. turns > 1), **training** performance drops substantially.

**User traits (COMMUNITY).** The 2nd-highest CM MAV block, driven predominantly by a large TG drop for users in the "(At most) Complete Secondary" education group. The authors rule out two obvious mediators — English proficiency and topic distribution show no difference — and instead trace the group to a **second recruitment wave** (Appendix F Table 6) targeted at less-educated participants. Conclusion: the RM memorizes a user trait tied to a *data-collection artifact*, mediated through those users' prompts and preferences. This is the paper's most striking single result.

### Finding 3 — Overgeneralization of heuristic correlates

Most annotated features have **larger MAV for TG than TM**, i.e. the RM leans on them more for unseen pairs and attenuates them for seen pairs.

**Rule-based rewards & sycophancy (Figure 5).** Reported HMR values (secondary axis), preserved as printed:

- PRISM, in the figure's label order (Third Person, Disclaimer, Framing, Non-Compliance, Meta Commentary, Judgement, Safety Policy, Definitive Verbiage, Professional Help, Encourage Help, Indirectness, Ack. Emo. State, Hedging, Prescribes Solutions, Provides Resources, Validation, Full Compliance, Partial Compliance): **2.56, 5.32, 5.35, 31.14, 5.34, 17.74, 43.55, 30.29, 50.81, 41.80, 23.82, 57.17, 43.72, 25.14, 7.27, 13.71, 5.08, 2.27**
- COMMUNITY, in order (Judgement, Framing, Disclaimer, Indirectness, Hedging, Meta Commentary, Encourage Help, Prescribes Solutions, Validation, Ack. Emo. State, Third Person, Professional Help, Provides Resources, Definitive Verbiage, Non-Compliance, Full Compliance, Partial Compliance, Safety Policy): **4.18, 11.72, 14.41, 19.25, 15.74, 12.22, 11.29, 19.95, 20.21, 10.75, 19.79, 21.35, 5.07, 8.69, 5.70, 10.52, 8.87, 1.69**

Substantive readings:
- **Partial or full compliance** produces the largest expected-SHAP gains for **both TM and TG** in both datasets — the presence of a compliance difference makes reward assignment substantially easier. Compliance also carries the best (lowest) HMR ranks: PRISM Partial Compliance 2.27, Full Compliance 5.08; COMMUNITY Partial Compliance 8.87, Full Compliance 10.52 with Safety Policy at 1.69.
- **Non-compliance/refusal** yields substantially worse performance.
- In PRISM, other refusal-adjacent features (Disclaimer, Meta-Commentary) yield **large CM gains**. Conclusion: RMs generalize naturally to compliant responses but must **memorize refusals** — a direct safety concern, since refusals are exactly where correct reward assignment matters most.
- **Sycophancy as a block contributes minimally** to TM or TG. But the single feature **Framing** (unquestioningly adopting the user's frame) has high CM in **both** datasets, driven by a marked test-time drop when Framing is present only in the chosen response.

**Complexity/length.** The classic verbosity bias appears with a clean asymmetry (Appendix H Figure 13): when the chosen response is *more* complex than the rejected one, large **negative** CM SHAP; when the chosen is *less* complex, the opposite. Restated: RMs generalize when the pair agrees with the learned length heuristic and must **memorize heuristic violations**.

### Data-driven results (SAE, Figure 6)

**PRISM — clear region differentiation:**
- **high TM / high TG:** long, neutral, maximally compliant responses ("uses structured, formatted documents or lists", "does not use AI-disclaimer neutrality hedging", "is written in English").
- **maximum-CM region (high TM / low TG):** brief chosen responses, sometimes a **single word** ("gives brief, non-elaborated responses", "gives only a one-word affirmation") — i.e. explicit violations of the length heuristic.
- **medium/medium:** non-neutral responses to controversial, politically charged topics ("states a definite stance on sensitive issues", "avoids giving political opinions or analysis") — cases where *multiple responses could legitimately be preferred* depending on user stance, i.e. genuine user–user preference conflict.

**COMMUNITY — weak differentiation**, attributed to all responses coming from one model. Formatting recurs across all regions; references/resources are especially prevalent in low/low; response topic discriminates the two middle regions from the outer two.

**Synthesis offered:** heuristic-aligned pairs → high/high; heuristic-violating pairs → high/low (high CM); low-entropy/conflicting preference distributions → medium/medium.

### Statistical significance

- Multiple-comparison control is applied **only** to SAE feature descriptions (Bonferroni, α=0.05).
- **No confidence intervals, standard errors, or significance tests** are reported for R² values, MAV, HMR, or any SHAP partial effect — despite these being averages over ensembles where variance is computable (and where TG rests on only 5 runs per pair). Words like "substantially", "significantly smaller", and "marked reduction" are used without accompanying statistics.

## 9. Review

### Experimental Strengths

- **Well-posed, novel measurement target.** Applying counterfactual memorization to RMs is genuinely new; the TM/TG decomposition gives a principled way to separate *memorization* from *overgeneralization* using the sign of CM, and the paper uses that distinction consistently.
- **Serious cross-fitting design.** 25 RMs per dataset with a controlled 20/5 inclusion pattern is real compute discipline for an analysis paper.
- **User-level splitting.** Splitting by user rather than by pair, plus explicit attention to user–user confounding, correctly addresses the leakage that would otherwise inflate TG in preference data where a single user labels many turns.
- **Two independent explanation routes converge.** The hand-designed feature/SHAP route and the SAE route independently surface the brevity/length-violation story in PRISM. Convergent evidence from methods with different failure modes is worth more than either alone.
- **Honest self-confounding checks.** The margin finding is flagged as partly by-construction in PRISM and then shown to replicate in COMMUNITY. The COMMUNITY user-education finding is stress-tested against two alternative mediators (English proficiency, topic) before the recruitment-wave explanation is offered.
- **The recruitment-wave result is a strong, concrete demonstration** that RMs memorize data-collection artifacts, not just linguistic surface features. That is a more consequential claim than the well-known length bias and it is supported by a plausible causal chain.
- **Practically pointed safety finding.** "RMs generalize to compliance and must memorize refusals" is exactly the asymmetry that would predict the reward-hacking behaviors catalogued in the introduction.

### Experimental Limitations

**Setup and generalizability**
1. **Single, very small backbone.** All conclusions rest on Llama-3.2-1B. Memorization is strongly scale-dependent; there is no evidence the observed patterns hold at the 7B–70B scale where production RMs live.
2. **LoRA-only training.** Trainable capacity is heavily restricted, which directly affects the phenomenon being measured. Appendix D reportedly discusses this, but no empirical full-finetune comparison is indicated. Without it, "RMs misallocate memorization capacity" could plausibly be "LoRA RMs have little capacity to allocate."
3. **Unspecified SFT stage.** The SFT corpus is never named in the main text. If SFT touched the same conversations, the "held-out" condition is not cleanly held out and TG is inflated, which would shrink CM everywhere.
4. **Two datasets, both single-turn-labeled human-preference corpora from the same recent research lineage.** No standard RM training set (HH-RLHF, UltraFeedback, Nectar), so it is unknown whether the shortcuts are properties of these datasets or of preference data generally.
5. **No RM quality anchor.** Without accuracy on a held-out preference set or a public benchmark, we cannot tell a well-trained RM exhibiting real biases from an undertrained one exhibiting artifacts.

**Estimator design**
6. **Asymmetric estimator variance.** TG averages 5 runs vs TM's 20. Since CM = TM − TG, essentially all CM noise comes from the TG term. The paper acknowledges this only indirectly ("we attribute to noise" for negative CM). No variance estimates, no bootstrap, no reliability check on per-pair CM.
7. **CM is not corrected for ceiling effects.** With most pairs already near TM=TG=1, CM is mechanically compressed for easy pairs and can only be large where TG is low. Some of the "high-margin pairs get high CM" result could be a ceiling/floor artifact rather than a capacity-allocation phenomenon. No normalized alternative (e.g. CM relative to headroom) is examined.

**Attribution validity**
8. **SHAP explains the surrogate, not the RM.** With CM R² of 0.39/0.33, roughly two-thirds of the variance being attributed over is unmodeled. Feature importance from a mediocre surrogate is a weak proxy for RM mechanism.
9. **Correlational throughout; no interventions.** Nothing in the paper tests causality by editing responses — e.g. lengthening a chosen response, swapping a model's stylistic signature, or paraphrasing a refusal — and re-measuring. Every "the RM relies on X" claim is an association in feature space.
10. **LLM-generated features are unvalidated in the main text.** 84 features from unnamed LLM annotators, with no reported human agreement, calibration, or error rate. Emotion (28) and dialog acts (23) dominate the feature count and are exactly the categories where LLM annotation is least reliable. Annotation error attenuates SHAP unevenly across blocks, which can reorder Figure 3.
11. **No multiple-comparison control on the SHAP analyses.** With 84 features × 3 targets × 2 datasets plus block aggregates, and Bonferroni applied only to SAE descriptions, several highlighted single-feature effects (e.g. Framing) are at real risk of being selection artifacts.
12. **Rare-feature instability, acknowledged but unquantified.** Footnote 3 concedes that feature differences in COMMUNITY are "exceedingly rare", making SHAP unreliable — but no support counts or minimum-frequency filter are reported, so readers cannot tell which Figure 5 bars are trustworthy.
13. **SAE evidence is thin.** 32 latents with ~4 active is a very small dictionary for ~195k pairs; the region classifier is a linear head whose weights are read as interpretation; the region thresholds are unstated; and by the authors' own admission COMMUNITY shows little differentiation. Figure 6 is suggestive, and the paper words it appropriately ("tentatively suggest"), but it cannot bear much weight.
14. **LLM-in-the-loop labeling with gpt-5/gpt-5-mini** introduces an unversioned, non-reproducible dependency into the interpretation pipeline.

**Claim scope**
15. **The reward-hacking claim is not tested.** The introduction and abstract motivate everything via reward hacking during RLHF, but no RLHF/PPO/DPO run is performed. The link from "high CM on refusals" to "verbose sycophantic chat models" remains an inference.
16. **The conclusion is stated more strongly than the evidence supports.** "Not yet capable of judging response quality in context-dependent scenarios" is a claim about RMs in general, established on one 1B LoRA setup and two datasets.

**Reporting inconsistencies noted**
17. Figure 3b's axis is labeled **"MANV"** where 3a and the text use **"MAV"** — presumably a typo, but it is the paper's central figure.
18. **COMMUNITY pair count:** 45.8k turns × 4 responses implies 274.8k pairs; 137k are reported, almost exactly half, with no explanation in the main text.
19. **Figure 5 feature count:** the text defines 16 rule-based rewards + 3 sycophancy = 19 features, but both panels list **18** labels and 18 HMR values. One feature is unaccounted for, and the figure does not mark which of the 18 are the sycophancy features (Framing is discussed as sycophancy; Validation and Ack. Emotional State are plausible but unlabeled).
20. **Figure 6's region definitions** are given as low/low, medium/medium, high/low, high/high, while §5 and §7 refer to the max-CM region as "medium to high train memorization" — slight drift in how the same region is described.
21. Figure 1's caption contains a typo ("counteractual"), and Figure 1 is cited both for the CM concept and for the 4-region partition, though the region thresholds do not appear there.

### Reproducibility Assessment

**Overall score: Medium** (would be Medium-Low judged on the main text alone; the public code repo and the stated existence of Appendices B, D, E is what lifts it).

**What supports reproduction:** public code repository; both datasets publicly available; open backbone checkpoint; clearly specified metric (Eq. 2); clearly specified ensemble design (25 subsets, 20 in / 5 out, user-level split); SAE architecture family and sparsity budget given; SHAP variant (conditional) and background-set size (1k) given; regressor eval split (20%) given.

## 总结（中文）

这篇论文首次把「反事实记忆」（counterfactual memorization, CM）的分析框架用到判别式奖励模型（RM）上。做法是：在 PRISM 与 COMMUNITY 两个人类偏好数据集上，以 Llama-3.2-1B 为骨干、走 LM→SFT→RM 流程并用 LoRA 训练 **25 个** RM，每个偏好对恰好出现在 20 个子集的训练集中、在另 5 个中被留出，从而分别估计训练记忆 TM 与测试泛化 TG，二者之差即 CM；划分在**用户层面**进行以避免偏好泄漏。随后用 84 个 LLM 标注特征（外加数据集元数据）训练 3 层 MLP 回归 TM/TG/CM，并用 SHAP 做归因（留出 20%，1k 样本作扰动集），held-out R² 分别为 0.56/0.63（TM）、0.52/0.38（TG）、0.39/0.33（CM）。另外复现了 Movva 等人的 RM-SAE（≤32 个隐变量、平均激活 4 个），在响应嵌入差上训练并附加 CM 四区域分类损失，用 gpt-5 生成隐变量描述、gpt-5-mini 验证并做 Bonferroni 校正。

三个主要结论：一是记忆容量被**错配到高偏好边际的简单样本**上（PRISM 中边际进了损失函数，但该效应在 COMMUNITY 中同样出现，说明不只是构造产物）；二是 RM 会记住与人类偏好无因果关系的**数据集专有捷径**——PRISM 中是回复模型身份，COMMUNITY 中是「至多中等教育」用户群，而该群体几乎全部来自第二轮招募，属于数据采集产物；三是对**长度、顺从性等启发式相关量过度泛化**：顺从（partial/full compliance）显著提升 TM 与 TG，而拒答需要靠记忆，SAE 也独立发现最高 CM 区域正是「极简短、甚至单词回复」这类违反长度启发式的样本。

主要实验缺陷：只有单一 1B 骨干且仅用 LoRA，而记忆本身高度依赖容量，缺少全参数微调与更大规模的对照；TG 只由 5 次运行估计，CM 的噪声几乎全来自该项，且全文未报告任何方差或显著性；SHAP 解释的是拟合度仅 0.33–0.39 的代理回归器而非 RM 本身；全程为相关性分析，没有做文本干预来验证因果；SFT 数据、优化器、学习率、批大小、硬件与四个区域的数值阈值均未在正文给出；标题所依赖的 reward hacking 论断也没有任何 RLHF 下游实验支撑。此外发现若干报告不一致：图 3b 轴标签写作 MANV、COMMUNITY 的偏好对数量（137k）恰为组合数（274.8k）的一半却无解释、图 5 按正文应有 19 个特征但只列出 18 个。**附录 A–H 未包含在所提供内容中**，而图 3 的数值、边际相关性、SAE 特征全表均只存在于附录，因此这些结论无法核验。复现性评级：**中等**（有公开代码与公开数据集，但正文超参数与实现细节严重不足）。

### 3.3 Method configuration (objectives, as specified)

All arms share the GRPO surrogate with clipping; they differ only in the per-token or per-sequence weight applied to the gradient:

- **BF16 baseline:** Eq. (1), inference and training both high-precision → discrepancy comes only from engine/kernel/nondeterminism, not quantization. This is the accuracy reference.
- **FP8 (uncorrected):** Eq. (1) with FP8 rollout. Serves as the failure case.
- **TIS:** Eq. (2), weight `min(ρ_{i,t}, C)` with `ρ_{i,t} = π(a_{i,t}|·,θ_old)/µ(a_{i,t}|·,θ_old)` — token-level truncated IS.
- **MIS:** Eq. (3), weight `ρ_i · 1{ρ_i ≤ C}` with sequence-level `ρ_i = π(a_i|q,θ_old)/µ(a_i|q,θ_old)` — unbiased but high-variance.
- **ACRL:** Eq. (10), identical in form to TIS but with `ρ_{i,t} = (π/µ)^α` and `α = γ · sign(A_{i,t}) · (1 − Y/X)`, where `Y` is the current sequence's mean absolute discrepancy.

Sign-logic verification (my own check): for `Y > X`, `(1 − Y/X) < 0`. With `A > 0` this gives `α < 0`, so `π < µ` ⟹ `ρ > 1` (reward enhancement) and `π > µ` ⟹ `ρ < 1` (reward reduction) — matching the Quadrant I/II statements in §4.2. With `A < 0`, `α > 0` and the Quadrant III/IV statements follow. **The algebra in §4.2 is internally consistent with Eq. (12).** ACRL reduces exactly to TIS when α = 1, i.e., TIS is the special case γ·sign(A)·(1−Y/X) = 1, and to plain GRPO when α = 0 (i.e., Y = X).

One quantitative consequence worth flagging: with γ ≤ 0.65 and Y/X typically near 1 early in training, |α| ≪ 1, so ρ = (π/µ)^α sits very close to 1 and the correction is *mild*. The paper's stability claim therefore rests on a weight that is much gentler than TIS's raw ratio. This is plausible as a variance-reduction story (a fractional power compresses extreme ratios toward 1, which is precisely why MIS-style vanishing/exploding weights are avoided), but the paper offers no measurement of the realized α, ρ, or Y/X distributions to substantiate it. That measurement is the most important missing diagnostic in the whole evaluation.

### 3.4 Evaluation protocol
- **Metrics:** accuracy (Tables 1–3); "avg. Acc (last 200 steps)" as a stability-aware secondary metric on GSM8K; training entropy as a dynamics metric (Fig. 8); binary success/failure to denote training collapse (Table 2).
- **Definitions not given:** how "Acc" in Table 1 is selected (final step? best step?), what constitutes "failure" operationally (loss NaN? entropy collapse? reward collapse?), how answers are verified, and whether evaluation uses greedy or sampled decoding.
- **Validation strategy:** no dev/validation split is described; γ ∈ {0.35, 0.65} is reported directly on the test benchmarks (Table 3), so the winning γ is selected on test data.
- **Statistical treatment:** no seeds, no variance, no confidence intervals, no significance tests anywhere in the visible content.

## 4. Baselines

### 4.1 BF16 (high-precision reference)
- **Type:** GRPO with BF16 rollout, no correction.
- **Purpose:** accuracy ceiling / "correctness" reference; the paper's target is to *match* it while keeping FP8 speed.
- **Strengths:** the right reference — it isolates quantization as the variable.
- **Limitations:** it is not free of discrepancy (engine and kernel differences persist), and the paper does not report its measured discrepancy, so "matches BF16" is an accuracy statement with no accompanying discrepancy measurement for the reference itself.
- **Fairness:** high, assuming identical hyperparameters. Not verifiable from the text.

### 4.2 FP8 (uncorrected)
- **Type:** GRPO with FP8 rollout, no correction. The negative control.
- **Result:** marked failure (×) in Table 2. Notably, **FP8 has no row in Table 1** even though it appears in Figure 8's legend. Either it collapsed on standard FP8 too (in which case Table 1 should say so) or its number was omitted. This is an unexplained inconsistency between the figure and the table.

### 4.3 TIS — token-level truncated importance sampling (Yao et al., 2025; Liu et al., 2025b)
- **Type:** per-token truncated IS weight, Eq. (2).
- **Implementation details:** only C is needed and C is not reported. Otherwise identical objective to ACRL, which makes it the tightest and most informative comparison in the paper: TIS vs. ACRL differs *only* in the exponent α.
- **Strengths:** low variance, easy to implement, well-established.
- **Limitations acknowledged by the paper:** biased; ignores sequence-level discrepancy.
- **Fairness:** high in form. But since C is unreported and untuned-as-documented, TIS may be handicapped by an arbitrary truncation choice while ACRL's γ was explicitly swept.

### 4.4 MIS — sequence-level masked importance sampling (Liu et al., 2025a)
- **Type:** sequence-level ratio with hard mask, Eq. (3).
- **Strengths:** unbiased gradient estimator (the paper's own framing).
- **Limitations:** vanishing weights, high variance, slow convergence; fails under truncated FP8 (Table 2).
- **Fairness:** reasonable, though the mask threshold C is again unreported. The paper's critique of MIS (vanishing ratios) is asserted from prior work rather than measured here — no plot of realized ρ_i or of the fraction of masked sequences is provided, which would have been the direct evidence.

### 4.5 Missing baselines
- **Precision-alignment methods that the introduction explicitly argues against**: FP8-everywhere (LMSYS Org, 2025) and FP16-alignment (Qi et al., 2025). These are named as the main competing family, yet neither appears in any visible table. Their absence undercuts the introduction's argument, which is partly an efficiency/accuracy argument against alignment.
- No KL-penalty or trust-region baseline, no simple ratio-clamping baseline, no "resample/reject high-discrepancy sequences" baseline.
- No throughput/efficiency comparison in the visible text (promised in 5.4), so the central motivating trade-off — FP8 speed vs. accuracy — is never quantified where I can see it.

## 5. Experimental Process (Step-by-Step, as reconstructable)

Reconstructed from Sections 4–5.1. Steps marked **[unspecified]** are not documented in the provided content.

**Step 0 — Reference calibration (pre-training).**
1. Load initial policy weights (Qwen2.5-3B-Instruct or Qwen2.5-7B-Base).
2. Run rollouts on a baseline set of *n* questions (**[unspecified]** which set, how large) with the FP8 inference engine to obtain µ probabilities, and recompute the same token probabilities with the BF16 training engine to obtain π.
3. For every token, compute `d = |π − µ|` (Eq. 8).
4. Average over tokens, over the G responses, and over the n questions to get the scalar reference **X** (Eq. 9). The paper's stated rationale: initial weights have not yet been contaminated by discrepancy-driven updates, so X is a "clean" baseline.
5. **[unspecified]** whether X is ever recomputed or held fixed for the whole run. The text implies fixed ("compiled before the training process starts"), and §5.3 was to probe robustness to this choice.

**Step 1 — Data preparation.** GSM8K for the 3B run; KlearReasoner-MathSub-30K for the 7B run. Prompt templates, answer-format instructions, max lengths, reward function, and dedup/contamination screening: **[unspecified]**.

**Step 2 — Rollout.** For each prompt q, sample G responses from the FP8-quantized vLLM policy µ(·|q, θ_old); record per-token µ log-probs.

**Step 3 — Recompute training-side probabilities.** Under FSDP/BF16, compute π(a_{i,t}|q, a_{i,<t}, θ_old) for the sampled tokens (standard VeRL old-log-prob recomputation). This is what makes d, Y, and ρ computable at zero extra rollout cost.

**Step 4 — Discrepancy measurement.** For each sampled sequence i, compute `Y` = mean over its tokens of `d(a_{i,t}, θ_old)`. (Eq. 12 uses a per-sequence Y; the definition text writes Y as an average over the group, which is a **notational ambiguity in the paper** — §4.1 calls Y "the current sequence's training-inference discrepancy" while the displayed formula averages over i = 1…G. These are different quantities and the distinction matters for whether the control signal is per-sequence or per-batch.)

**Step 5 — Advantage computation.** Group-normalized GRPO advantages `A_i = (R_i − mean{R})/std{R}`, broadcast to tokens.

**Step 6 — Adaptive weight construction.** `α = γ·sign(A_{i,t})·(1 − Y/X)`; `ρ_{i,t} = (π/µ)^α`; truncate with `min(ρ_{i,t}, C)`.

**Step 7 — Policy update.** Apply Eq. (10): the truncated adaptive weight multiplies the clipped GRPO surrogate gradient. Optimizer, LR, mini-batch structure, number of inner epochs: **[unspecified]**.

**Step 8 — Monitoring.** Track training entropy (Fig. 8) and, implicitly, reward/collapse status (used for the success/failure labels in Table 2). Collapse criterion: **[unspecified]**.

**Step 9 — Evaluation.** Periodic evaluation on GSM8K (3B) yielding both a headline accuracy and a mean over the last 200 steps; single-shot evaluation on the five hard benchmarks (7B). Decoding config and verifier: **[unspecified]**.

**Step 10 — γ sweep.** Two γ values reported (0.35, 0.65) for the 7B run. Whether more were tried, and on what data the choice was made: **[unspecified]** (Section 5.4 was to cover control-strength sensitivity).

**Step 11 — Ablation (announced, unavailable).** Section 5.5: disable the "increase discrepancy when Y < X" branch and compare against the full bidirectional controller. This is the ablation that would isolate the paper's most distinctive claim; I cannot evaluate it from the provided content.

## 7. Ablation and Analysis

**Announced but unavailable in the provided content:**
- §5.3 robustness to the reference baseline X (how it is computed, and behavior under extreme discrepancy) — this is the key design-assumption test, since X is computed once from initial weights and then held fixed while the policy drifts.
- §5.4 sensitivity to control strength γ and computational efficiency/overhead.
- §5.5 ablation of bidirectional adjustment (the "increase discrepancy when Y < X" branch), which the paper itself calls a "secondary robustness mechanism" (Remark 4.3). This is the one component that distinguishes ACRL conceptually from a variance-tempered TIS; without it, ACRL is a one-sided damping scheme.
- §5.2 scalability to larger models and other RL algorithms (DAPO etc.).

**Available in the provided content:**
- A partial γ sensitivity data point: γ ∈ {0.35, 0.65} on the 7B suite, with a 1.74 pp average swing between them (34.65 → 36.39). That is larger than the gap between any two baselines, which means γ is a first-order hyperparameter, not a minor knob. Two points do not establish a trend or an optimum.
- The exploration analysis (§4.3, Figs. 6–7) functions as a mechanism study: the four-quadrant AGPA amplifies PA&LP and NA&HP tokens (entropy-increasing) and suppresses PA&HP and NA&LP tokens (entropy-decreasing), which is offered as the causal explanation for both the entropy curve and the accuracy gain. The logic is coherent and testable, but the paper (in the visible part) does not test it directly — e.g., by reporting per-quadrant token mass, per-quadrant realized ρ, or an entropy-matched control.
- The paper is commendably explicit about its own theoretical cost: Remark 4.2 states plainly that the adaptive exponent makes ACRL a **biased estimator**, and defends this as a pragmatic trade (citing PPO/GRPO clipping precedent). Remark 4.3 ranks the two control directions by importance. Remark 4.1 flags the choice of |π − µ| as arbitrary among plausible metrics. This kind of self-disclosure is good practice, though it does raise the expectation that the bias's practical effect would be measured somewhere.

## 9. Review

### 9.1 Experimental Strengths
- The comparison set is the right one for the claim: BF16 ceiling, uncorrected FP8 floor, and the two state-of-the-art IS corrections (TIS token-level, MIS sequence-level) with their objectives written out explicitly (Eqs. 2, 3, 10), so the delta versus each is unambiguous at the algorithm level.
- ACRL differs from TIS by exactly one exponent, which makes the TIS row a near-perfect controlled comparison.
- Two scales (3B instruct, 7B base) and two difficulty regimes (GSM8K, hard competition math) rather than a single setting.
- The stability result is reported as a qualitative outcome (success/failure), which is the honest way to report collapse — Table 2 is the paper's most convincing evidence.
- Stability is measured with an appropriate secondary metric (mean accuracy over the last 200 steps), not just a best/final checkpoint number.
- Figure 6 provides real measurement in support of the mechanism argument rather than assertion alone.
- Explicit self-criticism of the estimator bias (Remark 4.2) and of the metric choice (Remark 4.1).
- The negative γ result (0.35 underperforming BF16) is reported rather than hidden.

### 9.2 Experimental Limitations

**Statistical power is the central problem.** Single run, single seed, single-pass evaluation, no variance reported. The headline 7B win (+1.28 pp average) reduces to roughly +2 problems on AIME24 and +1 on AMC23 against −1 on AIME25. On 30-problem benchmarks, a ±1-problem swing is ±3.33 pp, so the reported ordering of all five methods is inside the noise floor of the instrument. The claim "outperforms IS fixes" is not established at any reasonable confidence level by Table 3. Standard remedies (avg@8/avg@16 on AIME/AMC/HMMT, 3+ seeds, bootstrap CIs) are not applied.

**Hyperparameter selection on test data.** The two γ values are reported directly on the evaluation benchmarks, and the conclusion depends on which one is picked. With ACRL(0.35) at 34.65% (below BF16's 35.11% and MIS's 34.93%) and ACRL(0.65) at 36.39%, the method's headline claim is an artifact of selecting the better of two configurations on the test set. Meanwhile the baselines TIS and MIS receive no corresponding sweep of their own hyperparameter C — indeed C is never reported for any method. This is an asymmetric tuning budget, which is the classic way an ablation-style comparison becomes unfair even when the objectives are matched.

**The metric that best resolves differences shows no advantage.** MATH500 (n=500, 0.2 pp resolution) has a 1.0 pp total spread and MIS wins it. HMMT25 is at floor (1/30) for all methods and contributes nothing but dilution to the unweighted average. Effectively, the 7B conclusion rests on the two lowest-n, highest-variance benchmarks.

**Missing the baselines the paper argues against.** The introduction builds its case largely against precision *alignment* (FP8-everywhere per LMSYS Org 2025; FP16 per Qi et al. 2025) and asserts these lose accuracy or forfeit speed. Neither is evaluated in any visible table. The paper's positioning claim is thus argued but not measured.

**No efficiency measurement where visible.** The entire motivation is that FP8 rollout buys throughput and memory. ACRL adds per-token discrepancy computation, a per-sequence reduction, and a power operation. Without a throughput/memory comparison (promised in §5.4), the accuracy-vs-speed trade the paper is selling is unquantified in the available content.

**Under-instrumented mechanism.** The paper's core claim is that ACRL *keeps the discrepancy in a reasonable range*. Nowhere in the visible content is the discrepancy itself plotted over training for any method. There is no Y/X trajectory, no realized α or ρ distribution, no comparison of discrepancy curves for FP8 vs. TIS vs. MIS vs. ACRL. Figure 8 plots entropy, which is a downstream proxy. For a paper whose title is about controlling a quantity, the absence of a plot of that quantity is the most conspicuous experimental omission.

**Undefined critical conditions.** "Truncated FP8" — the setting that produces the paper's only qualitative win — is used in Table 2 without definition in the visible text. The FP8 recipe itself (E4M3 vs. E5M2, per-tensor vs. per-block scaling, which tensors are quantized) is never specified, so the severity of the perturbation cannot be judged or replicated. Similarly, "failure" is never operationally defined.

**Unexplained inconsistencies.**
- FP8 appears in Figure 8's legend but has no row in Table 1.
- BF16 accuracy differs between Table 1 (87.72%/86.60%) and Table 2 (85.90%) with no explanation of the configuration change.
- Table 1 does not state γ, so the 3B and 7B results may not use the same control strength.

**Design assumption untested in the visible content.** X is computed once from initial weights and then held fixed. **Overall score: Low** (based on the provided content; would likely rise to Medium if the appendix supplies standard hyperparameters, and to Medium-High if code is released — neither is verifiable from what I have).

The algorithm itself is reproducible on paper: Eqs. ## 2. Datasets

There is **no dataset** in the conventional sense. The single data source is a self-authored simulator, which is itself one of the paper's five stated contributions.

### 2.1 Continuous Grid Environment (custom)

**Source and domain.** Dynamics adapted from Barreto et al. (2017) (successor-features grid world), extended to a CMDP by the authors through the addition of cost cells. 2D navigation.

**State space.** `s_t = (α x_t, α y_t)` with `x_t ∈ [0, x_max] ⊂ ℝ`, `y_t ∈ [0, y_max] ⊂ ℝ`, and `α⁻¹ = max(x_max, y_max)`. Continuous, 2-dimensional. The `α` rescaling is a preprocessing step whose stated purpose is putting inputs into "a more sensible range for function approximation." Note the normalization is by the **larger** axis, so the shorter axis does not span [0,1] — the state is not isotropically normalized. `x_max` and `y_max` are never given numerically.

**Action space.** Discrete, |A| = 4 (up, down, left, right).

**Transition noise.** Step length `~ N(μ = 0.75, σ = 0.075)`, clipped to `μ ± 3σ` → step ∈ [0.525, 0.975]. Clipping is explicitly justified as simplifying wall-collision handling. Collision rule: if an action would place the agent inside a wall, the action is undone (full revert, not sliding).

**Reward function.** Deterministic. `+1` on reaching the goal cell; `−0.01` time penalty per step. No reward for cost avoidance.

**Cost function.** `J = 1` (single constraint). `+1` cost per step taken inside a cost cell. Cost is therefore a state-occupancy quantity, which is exactly the structure successor representations are best suited to — a favorable-by-construction setting worth noting.

**Termination / truncation.** Episode ends on reaching the goal. Truncated at 1000 environment steps. The authors state the environment is solvable in under 100 steps, and that the generous 1000-step cap deliberately lets a lost agent walk back to the start.

**Configurations / "splits".** Three difficulty levels by room count (1, 2, 3), each in a costed and costless variant. Layouts shown in Section D `[APPENDIX NOT PROVIDED]`, so the exact wall and cost-cell geometry — including how many cost cells exist and whether a cost-free path exists in the 3-room case — cannot be verified. This is a non-trivial gap: whether the 3-room environment admits a zero-cost path to the goal determines whether a safe goal count of 682 is near-optimal or near-failure.

**Splits.** None. There is no train/validation/test separation. All reported numbers are accumulated over training trajectories (see §4.3 and §9.2 for why this matters).

**Preprocessing.** For SafeDSR/SafeDQN, actions are one-hot encoded and concatenated to the state, giving a 2 + 4 = 6-dimensional network input `(s, a)`. Feature vectors are L2-normalized to `‖φ(s,a)‖²₂ = 1`.

**Comparison to standard suites.** The authors explicitly position the environment as similar to the Safety-Gymnasium goal task (Ji et al. 2023) but with lower-dimensional state and discrete actions, justified by ease of plotting trajectories and value functions for debugging/interpretation, plus tunable exploration difficulty via room count. The justification is reasonable; the absence of any Safety-Gymnasium run alongside it is the more significant issue (§9.2).

### 3.2 SafeDSR configuration (from Section 4.2)

Architecture, as reconstructible:

- **Feature network φ(s, a) → ℝᵈ.** Input: state ⊕ one-hot action. Output L2-normalized to unit norm. Layer sizes and `d` unknown.
- **Inverse feature network g: ℝᵈ → ℝ⁶.** Reconstructs `(s, a)` from φ.
- **Successor feature network M(φ) → ℝᵈ** (per Kulkarni et al. 2016, M takes φ as input, not the raw state).
- **Reward head w_r ∈ ℝᵈ** — linear, `R(s,a) ≈ φ(s,a) · w_r`.
- **Cost head w_c ∈ ℝ^{J×d}** — linear, `C(s,a) ≈ w_c · φ(s,a)`.
- **Target networks:** two — `M_prev` and, as a deviation from Kulkarni et al., `φ_prev`. The φ target network is introduced specifically to address the moving-target problem in Eq. (10).

Losses:

Successor-feature loss (Eq. 11):
```
L = ‖ φ_prev(s,a) + γ M_prev(φ_prev(s',a')) − M(φ(s,a)) ‖²₂
```
with `a'` selected greedily by the main network (DQN-style, not Double-DQN).

Feature/reward/cost loss (Eq. 14):
```
L_features = β_r (R(s,a) − φ(s,a)·w_r)²
           + β_c ‖C(s,a) − w_c·φ(s,a)‖²₂
           + β_g ‖(s,a) − g(φ(s,a))‖²₂
```
`β_r`, `β_c`, `β_g` values → Section B `[APPENDIX NOT PROVIDED]`.

Critically, the two loss groups are optimized **independently**: M's parameters receive no gradient from `L_features`, and φ/w_r/w_c receive none from Eq. (11). This is inherited from Kulkarni et al. (2016).

Action selection (Eq. 15):
```
argmax_a [ Q^π(s,a) − λ · (K^π(s,a) − b) ]
```
with ε-greedy exploration, **ε = 0.25** (stated in Section 5.3 text). Note the `− b` term inside the parenthesis is a constant offset independent of `a`, so it does not affect the argmax; it is a presentational artifact rather than an algorithmic component.

Lagrange multiplier update (Eq. 16), applied at episode end:
```
λ ← max(0, λ + α_λ (C_ep − b))
```
Proportional controller only. `α_λ` → Section B `[APPENDIX NOT PROVIDED]`.

Four documented modifications relative to DSR (Kulkarni et al. 2016):
1. State-action features φ(s,a) instead of state features φ(s), via one-hot action concatenation.
2. φ target network `φ_prev` added.
3. L2 normalization of φ.
4. Generalized biased sampling: instead of DSR's 80/20 replay/non-zero-reward split, they draw `20%/(J+1)` of the batch from each of the reward distribution and each of the J cost distributions, with probabilities inversely proportional to the respective distribution, and 80% uniformly from the replay buffer. With J=1 this means 10% reward-biased + 10% cost-biased + 80% uniform.
5. Feature network frozen after `t_freeze` environment steps (following Barreto et al. 2017) to stabilize M's input distribution. `t_freeze` value → Section B `[APPENDIX NOT PROVIDED]`.

### 3.3 SafeDQN configuration (Section 4.1)

- Standard DQN (Mnih et al. 2015) trained on cost-augmented reward `R̃ = R − λ·C`.
- Hyperparameters explicitly stated to be **based on the DQN implementation of Huang et al. (2022)** (CleanRL), with values in Section B `[APPENDIX NOT PROVIDED]`.
- Same λ proportional controller, same ε = 0.25 (the paper asserts "equal exploration strategy" to SafeDSR).
- Key structural difference from SafeDSR: λ enters the **learning target**, so any λ change invalidates the learned Q-function. In SafeDSR, λ enters only at decision time.

### 3.4 Baseline configuration

All 11 baselines: "the implementation and parameters from OmniSafe (Ji et al., 2024), specifically the experimental version developed by Zhou (2023) for discrete action spaces." No per-algorithm hyperparameters are reported. No tuning was performed as far as the text indicates — defaults were used.

### 3.5 Evaluation protocol

Metrics (Section 5.2):

- **Goal count:** number of training trajectories reaching the goal.
- **Safe goal count** (Eq. 17): `Σ_i 1(goal reached ∧ ∀j. C_j(τ_i) ≤ b_j)`.
- **Goal rate / safe goal rate:** time derivatives of the above.
- Both counts are monotonically increasing by construction, which the authors cite as a stability advantage over average episodic reward.

Aggregation pipeline, stated precisely:
1. Linearly interpolate each run's series onto support points every **200 environment steps**.
2. Aggregate across the 10 seeds at each support point using the **interquartile mean** (IQM, Agarwal et al. 2021).
3. For trend lines (average goal/safe goal rate), apply a **right-aligned moving average with window = 20,000 environment steps**.
4. For end-of-training scalars, take the last recorded event per seed and IQM across seeds.

The choice of IQM over the mean is well-motivated and cited. The order of operations (IQM across seeds *before* smoothing) is unambiguous.

### 4.1 SafeDQN as the controlled comparison

SafeDQN is the most valuable baseline in the paper and is well-designed as an ablation-by-substitution: same exploration (ε = 0.25), same Lagrangian controller, same value-based paradigm. The paper states "the main difference between SafeDQN and SafeDSR is just the parameterization of the Q-function as either a 'normal' neural network or a Deep Successor Representation." If that claim holds (it cannot be verified without Section B), the SafeDQN→SafeDSR delta is a clean attribution to the successor parameterization.

One caveat the text does not address: it is not literally only the parameterization. SafeDQN applies λ to the learning target; SafeDSR applies λ only at decision time. That is a second, independent design change, and it plausibly accounts for much of the gap on its own — Schmidt et al. (2022), which the paper cites in Section 4.1, isolates precisely that change without successor features. A three-way comparison (SafeDQN / decision-time-λ DQN with a separate K-head / SafeDSR) is the missing experiment that would separate "successor features help" from "decision-time λ helps."

### 4.2 Comparison fairness assessment

Several asymmetries work against the baselines:

**Tuning asymmetry.** SafeDSR/SafeDQN hyperparameters were chosen by the authors on this environment (Section B). Baselines run on library defaults. No tuning budget is reported for either side. This is the single largest fairness concern.

**Implementation maturity.** Baselines come from an "experimental" discrete-action port of OmniSafe (Zhou 2023). OmniSafe's validated algorithms target continuous-control Safety-Gymnasium tasks; the discrete-action variants are, by the paper's own wording, experimental. Poor baseline numbers may reflect the port rather than the methods. The paper does not report any sanity check that its baselines reproduce published results on any task.

**On-policy vs off-policy on a cumulative training metric.** Eleven of twelve baselines are on-policy policy-gradient methods; the two proposed methods are off-policy with replay. Goal count and safe goal count are integrated over training trajectories, which is a sample-efficiency measure, not a final-policy-quality measure. Off-policy value methods are expected to dominate on-policy methods on cumulative training counts in a small discrete task, independent of any successor-representation contribution. There is no final-policy evaluation (deterministic rollouts of the converged policy) anywhere in the provided content.

**Coupling between the metric and episode length.** Episodes end on goal or at 1000 steps. An agent that finds the goal completes short episodes and therefore accrues many trajectories per 500 k steps; an agent that does not gets truncated 1000-step episodes and accrues at most 500 trajectories. The metric therefore has a multiplicative rich-get-richer property that amplifies rather than measures the performance gap. This is visible in the data: SafeDSR's 3-room costless goal count is 4702, and 500,000/4702 ≈ 106 steps/episode, versus IPO's 6554 → 76 steps/episode. In the 3-room costed case, every baseline is at 0 safe goals; whether they are at 0 because of truncation-heavy episodes or because of constraint violation cannot be determined from Figure 4 alone.

**A partial offset in the baselines' favor.** SafeDSR's counts include ε = 0.25 exploratory actions, i.e. a quarter of its actions are random in every counted trajectory. That handicaps the proposed method on its own metric. It is a real point in the paper's favor, though the authors do not make it, and it also means the reported numbers understate SafeDSR's greedy-policy quality by an unknown amount.

### 4.3 Notable structural artifact in the baseline numbers

In the costless environment, the goal counts collapse into identical values within algorithm families:

- 1 room: CPO = OnCRPO = RCPO = TRPO-Lag = TRPO-PID = **25016**; CPPO-PID = P3O = PPO-Lag = **28130**
- 3 rooms: CPO = OnCRPO = RCPO = TRPO-Lag = TRPO-PID = **5523**; CPPO-PID = P3O = PPO-Lag = **6828**
- Costed 1 room: RCPO = TRPO-Lag = **448**

This is coherent and probably not an error: with `C ≡ 0`, every Lagrangian/constraint mechanism is inert, so TRPO-Lag, TRPO-PID, CPO, OnCRPO and RCPO all reduce exactly to TRPO under a shared seed, and the PPO-based trio reduces to PPO. The implication for the analysis is that the costless comparison has **~7 distinct algorithms, not 13** — the left panel of Figure 4 is much less informative than its 13 rows suggest, and the paper does not point this out.

One value breaks the pattern and should be flagged: in the 2-room costless setting, RCPO = **11498** while the rest of the TRPO family = **11508**. A 10-episode discrepancy under the reduction argument suggests RCPO's reward shaping is not perfectly inert at C ≡ 0 (a zero-multiplier still touching the objective or the RNG stream), or a seed-stream difference. Minor, but it undercuts a clean "identical by reduction" reading.

## 5. Experimental Process (Step-by-Step)

Reconstructed from Sections 4 and 5. Steps marked ⚠ are inferred, not stated.

### 5.1 Data preparation

1. Instantiate the grid environment at a chosen room count (1, 2, or 3); layouts per Section D `[APPENDIX NOT PROVIDED]`.
2. Select costed or costless variant. Costless = cost cells removed or cost function zeroed ⚠ (the text does not say which; it matters, because removing cells changes geometry while zeroing does not).
3. Reset: sample `s_0` from the initial state distribution μ — the start cell in Figure 3; whether the start is a point or a uniform-over-cell distribution is not specified.
4. Per step: rescale raw `(x, y)` by α; for SafeDSR/SafeDQN, concatenate the one-hot action to form the 6-D network input.

### 5.2 Interaction and buffer population (SafeDSR)

5. At state `s_t`, evaluate `φ(s_t, a)` for all four actions, push each through `M` to get `M̂(s_t, a)`, then apply the linear heads to obtain `Q̂ = w_r · M̂` and `K̂ = w_c · M̂`.
6. Select `argmax_a [Q̂ − λ K̂]`, or a uniform random action with probability ε = 0.25.
7. Step the environment (step length sampled and clipped; wall collisions revert the move). Receive `r_{t+1}`, `c_{t+1}`.
8. Store `(s_t, a_t, r_{t+1}, c_{t+1}, s_{t+1})` in the replay buffer.

### 5.3 Training updates (SafeDSR, per gradient step ⚠ cadence unspecified)

9. **Feature/reward/cost update.** Sample a mini-batch: 80% uniform from the replay buffer, 10% inversely-weighted by the reward distribution, 10% inversely-weighted by the cost distribution (the `20%/(J+1)` rule at J=1). Minimize Eq. (14) over φ, g, w_r, w_c.
10. **Successor-feature update.** Sample uniformly from the replay buffer (per Figure 2, the M update uses the uniform stream). Compute `a' = argmax` under the main network, form the target `φ_prev(s,a) + γ M_prev(φ_prev(s',a'))`, minimize Eq. (11) over M only.
11. Update target networks `M_prev`, `φ_prev` ⚠ (hard vs. soft update and cadence unspecified).
12. At `t = t_freeze` environment steps, freeze φ (and presumably g, w_r, w_c ⚠ — the text says only "the weights of the feature network φ", so whether the linear heads keep training after freeze is ambiguous and it matters for the adaptation claim).

### 5.4 Episode-boundary update

13. At episode end, accumulate episode cost `C_ep` and apply `λ ← max(0, λ + α_λ(C_ep − b))`. Note `C_ep` appears to be the **undiscounted** episodic cost, whereas the constraint in Eq. (1)/(3) is on the **discounted** sum. See §9.2.
14. For four Lagrangian baselines (PDO, RCPO, TRPO-Lag, PPO-Lag) and for SafeDSR, a variant with **delayed onset of λ tuning** was also run. Delay length is not given; results are described only qualitatively.

### 5.5 Hyperparameter tuning process

**Not documented.** No search space, search method, tuning budget, or selection criterion is described anywhere in the provided content. Section B lists "the used parameters," not how they were found. Given that the same 10 seeds and the same environments appear to be used for both tuning and reporting, there is no protection against selection-on-the-test-set for the proposed methods. This is the most consequential methodological omission.

### 5.6 Evaluation methodology

15. Log goal and safe goal events throughout training (no separate evaluation rollouts).
16. Run to 500,000 environment steps × 10 seeds × 6 configurations × 13 algorithms.
17. Interpolate to a 200-step grid → IQM across seeds → 20,000-step right-aligned moving average for rate curves.
18. Report end-of-training scalars as IQM of each seed's final logged value, rounded to integers in Figure 4.

### 5.7 Ablation study design

There is **no dedicated ablation section** in the provided content. What exists functionally:
- SafeDQN vs SafeDSR (parameterization, plus decision-time λ — confounded, see §4.1).
- Room count 1/2/3 as an exploration-difficulty sweep.
- Costed vs costless as a constraint-presence sweep.
- Delayed λ-tuning, reported narratively only.
- 5× environment steps for baselines, reported narratively only.

None of the five SafeDSR-specific design changes (state-action features, φ target network, φ normalization, generalized biased sampling, freezing) is ablated. Section 5.4 and Sections E–G might contain more; unavailable.

### 6.3 Performance patterns

**Where SafeDSR loses.** In the costless environments it is near the bottom: 22101 (1 room, rank ~12/13), 9317 (2 rooms, tied-lowest with PCPO's 9306 except PDO's 6920), 4702 (3 rooms, only PCPO and PDO lower). Consistent with the paper's admission that "many algorithms are capable of reaching the goal more often than SafeDSR." So the successor parameterization costs raw sample efficiency when there is no constraint to reason about. In the costed 1-room case it is also beaten by SafeDQN (8164 vs 3792, a 2.15× gap), TRPO-PID (6898, 1.82×), and CPPO-PID (5766, 1.52×).

**Where SafeDSR wins, decisively.** Costed 2-room: 2138 vs. second-best SafeDQN's 98 → **21.8×**, and vs. the best external baseline IPO's 9 → **238×**. Costed 3-room: 682 vs. **0 for all twelve other algorithms**. This is the paper's central empirical result and the magnitude is large enough that it is unlikely to be a tuning artifact alone, though see the caveats in §4.2.

**The scaling collapse of baselines.** From 1 to 2 rooms, external baselines lose 2–3 orders of magnitude of safe goal count (CPO 3056→3, IPO 3467→9, CPPO-PID 5766→0). SafeDSR loses less than 2× (3792→2138). The differential is the most informative pattern in the data: baselines are not merely worse, they fail categorically once exploration under constraints becomes non-trivial.

**Costless vs costed for SafeDSR (2-room).** 9317 goals without costs vs 2138 safe goals with costs → SafeDSR retains ~23% of its goal-reaching throughput when a constraint is added. For SafeDQN: 11340 → 98, i.e. ~0.9%. For IPO: 13240 → 9, ~0.07%. Note this ratio is not strictly apples-to-apples (goal count vs safe goal count, and the costed environment's geometry may differ), but as a rough robustness index it is stark.

**Rate dynamics (Figure 6, described in text, figure not provided).**
- 1 room: the seven best algorithms reliably find the goal after ≈250,000 environment steps. PID-Lagrangian methods reach >80% average safe goal rate by end of training; SafeDSR and SafeDQN settle around **70%**. The authors read this as evidence their proportional-only λ controller should be upgraded with integral and derivative terms — a candid and correct diagnosis.
- IPO shows "promising performance mid-training but eventually fail[s] to maintain safe trajectories," i.e. non-monotone/unstable behavior that an end-of-training scalar would hide. This is an argument for the rate curves that the missing Figure 6 would substantiate.
- 2 rooms: only SafeDSR exceeds **60%** average safe goal rate. 3 rooms: only SafeDSR exceeds **30%**.

**Qualitative trajectories (Figure 7, described only).** In the 2-room costed environment, CPPO-PID gets stuck in corners due to "overcorrecting behavior towards the cost cells"; RCPO gets stuck in local optima; SafeDSR and SafeDQN both route around cost cells to the goal. The authors attribute this to the high exploration rate ε = 0.25, which is an admission that part of the advantage is exploration, not representation — and one that further motivates the missing decision-time-λ-DQN control.

### 6.4 Reported narrative findings without supporting numbers

Three claims in Section 5.3 have no table, figure, or statistic attached:

1. "SafeDQN can reach a much higher average safe goal rate in the two-room environment given enough training steps" — an important qualification of the headline 2138 vs 98 result, with no number, no step count, no figure.
2. "even five-times as many environment steps did not improve the performance of the other algorithms significantly" — 2.5 M steps, no numbers, and "significantly" is used without a test.
3. Delayed λ-tuning "did only marginally change" the four Lagrangian baselines but improved SafeDSR — no delay value, no before/after numbers.

Claim 1 is the most consequential: it means the 2-room result is partly a statement about convergence speed at a fixed 500 k budget rather than about attainable performance. Claim 3 is a fairness concern in the opposite direction — the reported SafeDSR configuration appears to benefit from a delay that was tuned for it, and the text indicates the baselines were also tried with delays, but the reported Figure 4 numbers for SafeDSR presumably use the better variant while baselines use theirs. Without Section B it is not determinable which variant produced 2138 and 682.

### 6.5 Statistical significance

No significance testing anywhere in the provided content. No confidence intervals in the main figures — standard deviations are deferred to Sections F and G. IQM over 10 seeds is used, but Agarwal et al. (2021), which the paper cites for IQM, also recommends **stratified bootstrap confidence intervals**; those are not reported. The word "significantly" appears at least three times in Section 5.3 in a purely colloquial sense.

For the largest claims the effect sizes are big enough (682 vs 0 across 12 algorithms) that formal testing is unlikely to change the conclusion. For the closer comparisons — SafeDSR 3792 vs CPO 3056 in the costed 1-room, or SafeDSR 9317 vs PCPO 9306 in the costless 2-room — the absence of dispersion in the main text makes them uninterpretable.

## 9. Review

### 9.1 Experimental Strengths

- **Adequate seed count with a robust aggregator.** 10 seeds and IQM, with the citation to Agarwal et al. (2021), is above the median for this literature.
- **Fully specified aggregation pipeline.** 200-step interpolation grid, IQM-then-smooth ordering, 20,000-step right-aligned window, last-event IQM for scalars. Rare and commendable precision.
- **Broad baseline set from a maintained library.** 11 external algorithms spanning trust-region, Lagrangian, PID-Lagrangian, penalty, and interior-point families, taken from OmniSafe rather than reimplemented.
- **A well-constructed internal control.** SafeDQN is the right comparison to build, and it is far more informative than the 11 library baselines.
- **Difficulty axis.** The 1/2/3-room sweep converts a single result into a trend, and the trend (SafeDSR's advantage grows with exploration difficulty) is the paper's most persuasive evidence.
- **Costed/costless factorization.** Isolates whether the advantage comes from constraint handling or from general RL competence. The answer — constraint handling, since SafeDSR is below median without costs — is a genuinely informative negative result the authors report rather than hide.
- **Environment specified analytically.** Noise distribution with parameters, clipping rule, collision rule, reward values, cost rule, truncation limit, and the rationale for the truncation limit are all in the main text.
- **Metric definition is formal.** Eq. (17) is explicit, and the motivation (single interpretable number; avoids trading reward against cost; robust to cost outliers; comparable across environment changes where absolute reward is not) is well-argued.
- **Candid self-criticism.** The authors state that many algorithms beat SafeDSR without costs, that their proportional controller likely needs I and D terms, that SafeDQN may catch up with more steps, and that the environment "does not fully represent the challenges addressed by modern RL techniques."

### 9.2 Experimental Limitations

**The central claim is untested in the available experiments.** Sections 5.1–5.3 use a fixed cost function throughout. Fast adaptation to cost-structure change — the paper's stated motivation, its title's implicit promise, and the entire justification for the successor decomposition — is confined to Section 5.4, absent here. Even taking Section 5.4's existence on faith, the design questions that determine whether the claim is meaningful are unanswerable: does the new cost function lie in the span of the frozen features φ? Is φ re-trained or only `w_c`? Is the comparison against baselines-retrained-from-scratch or against baselines-fine-tuned? What counts as "a few environment interactions"?

**The linear-in-φ assumption interacts badly with feature freezing, and this is not examined.** The paper argues the assumption `C(s,a) ≈ w_c · φ(s,a)` is "without loss of generality, since any component of φ(s) can learn to replicate the reward." That argument requires φ to be trainable. After `t_freeze`, φ is fixed, so cost adaptation is restricted to re-weighting a frozen basis. Any new cost function outside the span of the frozen features cannot be represented, and the method's flexibility is bounded by whatever the initial cost distribution taught φ to encode. This is the key theoretical limit on the paper's contribution and there is no experiment probing it — no test with a cost pattern structurally unlike the training one, no `d` sweep, no measurement of post-adaptation cost-prediction error.

**Hyperparameter tuning is entirely undocumented, and the asymmetry favors the proposed method.** SafeDSR/SafeDQN parameters were set by the authors on the reported environments; baselines use library defaults. No search space, budget, protocol, or validation split is reported for either. With no train/test separation and the same 10 seeds used throughout, the reported SafeDSR numbers are best read as in-sample. Additionally, Section 5.3 reveals that λ-tuning-delay was explored as a variant and that it helps SafeDSR specifically — meaning the reported configuration may include a per-method tweak that the baselines did not receive in equal measure.

**The evaluation metric structurally favors off-policy methods and is coupled to episode length.** Goal count and safe goal count integrate over training trajectories. This is a sample-efficiency measure, so comparing replay-based off-policy methods against 11 on-policy policy-gradient methods on it is not a comparison of algorithmic quality. Worse, because episodes terminate on goal and truncate at 1000 steps, an agent that succeeds accrues many short episodes while an agent that fails accrues few long ones — the metric multiplies the gap rather than measuring it. The paper has **no final-policy evaluation at all**: no deterministic greedy rollouts, no held-out evaluation episodes, no reporting of converged constraint satisfaction. This is a serious protocol gap for a safety paper, where the practically relevant question is whether the *deployed* policy satisfies the constraint.

**Discount mismatch between the constraint, the controller, and the metric.** Eq. (1) and Eq. (3) define the constraint on the *discounted* cost sum `Σ γᵗ C(s_t,a_t) ≤ b`. Eq. (16) updates λ using `C_ep`, described as "the episode cost," apparently undiscounted. Eq. (17) checks `C_j(τ_i) ≤ b_j` on "the observed costs of trajectory τᵢ," also apparently undiscounted. With γ = 0.99 over episodes up to 1000 steps, discounted and undiscounted cost differ substantially. So three different quantities are being conflated: the theoretical constraint, the quantity the controller regulates, and the quantity the metric scores. The paper does not acknowledge this. It applies to the baselines too (OmniSafe's Lagrangian methods typically regulate undiscounted episodic cost), but it means the reported "safe" designation does not correspond to the CMDP being solved.

**One environment, and a deliberately easy one.** 2-D continuous state, 4 discrete actions, deterministic reward, single constraint, solvable in <100 steps. The paper explicitly notes similarity to Safety-Gymnasium's goal task but runs nothing on Safety-Gymnasium, despite using OmniSafe, whose baselines are validated there. This forecloses the most obvious sanity check: do the 11 baselines behave as published on any task? Without it, the claim "only SafeDSR reaches the goal safely in 2 and 3 rooms" cannot be distinguished from "the experimental discrete-action OmniSafe port underperforms."

**J = 1 throughout, but the method is presented for general J.** The generalized `20%/(J+1)` sampling rule and the matrix-valued `w_c ∈ ℝ^{J×d}` are the multi-constraint machinery, and the multi-constraint case is never run. The claim that SafeDSR handles multiple constraints is architectural, not empirical.

**SafeDQN's confound.** SafeDQN differs from SafeDSR in *two* ways, not one: the Q parameterization and where λ enters (learning target vs. decision rule). The paper attributes the gap to the first while describing the second as the key insight of Section 4.2. The paper even cites Schmidt et al. (2022) as the method that makes only the second change, then does not run it. The 21.8× gap is real but unattributed.

**Reported advantages are partly credited to exploration by the authors themselves.** Section 5.3 attributes the SafeDSR/SafeDQN routing behavior in Figure 7 to "their high exploration rate (ε = 0.25)." No baseline exploration rates are reported, and no ε sweep exists. If ε explains a meaningful share of the advantage, the successor-representation contribution is overstated.

**No statistics in the main results.** No CIs in Figures 4/5, no hypothesis tests, no bootstrap intervals despite citing the paper that recommends them. "Significantly" is used colloquially. Standard deviations exist only in appendices.

**Un-numbered narrative claims.** The 5×-steps result, the delayed-λ result, and the "SafeDQN catches up eventually" qualification are all asserted without data. The third one directly weakens the headline comparison and deserves a figure.

**Missing datum in Figure 4.** The right panel reports safe goal count but not goal count for the costed environments. A zero therefore conflates "never found the goal" with "found it but always violated the budget" — two very different failure modes with very different implications for whether the baselines are exploration-limited or constraint-limited. The paper's own diagnosis (exploration) is based on Figure 7 trajectories, not on this table.

**No compute or runtime reporting.** Framework, hardware, wall-clock time, and per-step cost appear nowhere in the main text, and no appendix reference promises them. Since a stated criticism of Schmidt et al. (2022) is that learning multiple predictors is "computationally expensive," and SafeDSR itself adds a feature net, inverse-feature net, successor net, two target nets, and two linear heads, the absence of any efficiency measurement leaves that argument unsupported in both directions.

**Reported goal counts imply a plausibility check the paper does not perform.** SafeDQN's 3-room costless goal count of 7518 over 500,000 steps is ~66 steps/episode in an environment the authors say is solvable in "fewer than 100 steps" — with ε = 0.25 random actions. That is tight but not impossible if the 3-room optimal path is short; it is unverifiable without Section D. Worth checking against the layouts.

1. **A cost-shift adaptation experiment with a proper protocol** — new cost patterns both inside and outside the span of frozen φ, compared against baselines re-trained from scratch *and* fine-tuned, with adaptation-steps-to-threshold as the metric.
2. **A held-out greedy-policy evaluation** — periodic deterministic rollouts reporting average episodic reward and cost, so final constraint satisfaction is measurable independently of training-time exploration.
3. **The decision-time-λ DQN control** (Schmidt et al.-style Q + K heads without successor features) to disentangle the SafeDQN→SafeDSR gap.
4. **Safety-Gymnasium results**, even on one discrete-action task, to validate the baseline port.
5. **Ablations of the five DSR modifications**, plus a `d` sweep and an `ε` sweep.
6. **A `b` sweep and a J > 1 experiment** to exercise the multi-constraint machinery.
7. **Stratified bootstrap CIs** in the main figures, per the cited Agarwal et al. protocol.
8. **Numbers for the three narrative claims**, especially SafeDQN's long-horizon 2-room catch-up.

### 9.4 Noted inconsistencies in reported results

1. **RCPO = 11498 vs. the TRPO family's 11508** in the costless 2-room setting, while RCPO matches the family exactly at 1 room (25016) and 3 rooms (5523). If the match is by reduction-to-TRPO at C ≡ 0, the 2-room value should match too.
2. **Widespread exact duplicate values across algorithms** in the costless panel (25016 ×5, 28130 ×3, 5523 ×5, 6828 ×3, 11508 ×4, 12278 ×3) and once in the costed panel (RCPO = TRPO-Lag = 448). Explicable as family reduction under shared seeds, but unremarked by the authors, and it reduces the effective baseline count in the costless comparison from 13 to ~7.
3. **Discount inconsistency** between Eq. (1)/(3) (`Σ γᵗ C ≤ b`), Eq. (16) (`C_ep`), and Eq. (17) (`C_j(τ_i)`).
4. **Redundant `− b` term in Eq. (15)** — constant in `a`, so it cannot affect the argmax. Presentationally misleading about the decision rule.
5. **Figure 4's costed panel omits goal count**, making the many zeros in the safe goal count ambiguous between two distinct failure modes.
6. **"Equal algorithms" claim** in Section 5.3 ("despite having an equal exploration strategy and using equal algorithms") overstates the SafeDQN/SafeDSR equivalence, since λ placement also differs.
7. **Section E is never cross-referenced** in the provided text, so either a reference is missing or the appendix lettering skips E.

## 总结（中文）

这篇论文提出 SafeDSR，把 Deep Successor Representation 扩展到约束强化学习：通过一个可学习的权重矩阵把动力学、奖励、成本解耦，使成本结构变化时只需以监督方式更新单步成本预测器，而不必重训整个网络。同时论文提出 SafeDQN 作为受控基线，并引入 safe goal count / average safe goal rate 作为单一可解释的评估指标。

实验规模：自建的二维连续状态网格环境，6 种配置（1/2/3 房间 × 有无成本），13 个算法，10 个种子，每次 50 万环境步，共约 780 次运行。核心结果：在无成本环境中 SafeDSR 排名靠后（1 房间 22101，垫底附近）；但在有成本环境中优势随探索难度急剧扩大——2 房间 safe goal count 为 2138，次优的 SafeDQN 仅 98（21.8 倍），最好的外部基线 IPO 仅 9（238 倍）；3 房间 SafeDSR 为 682，其余 12 个算法**全部为 0**。

主要优点：种子数与 IQM 聚合规范、聚合流程描述极为精确、基线覆盖面广且取自 OmniSafe、SafeDQN 这一内部对照设计合理、有无成本与房间数两个维度的因子化设计信息量高、作者对自身缺陷（比例控制器需加入 I/D 项、环境过于简单、无成本时不如基线）态度坦诚、代码已开源。

关键问题：**论文的核心主张在可获得的实验中完全没有被检验**——5.1 到 5.3 节全部使用固定成本函数，快速适应成本变化的证据集中在缺失的 5.4 节。其次，特征网络在 `t_freeze` 后被冻结，这使"线性假设不失一般性"的论证失效：成本适应被限制在冻结特征张成的子空间内，而论文没有任何实验探测这一边界。第三，超参调优过程完全未记录，且提出方法在本环境上调过参、基线使用库默认值，存在系统性不对称；文中还透露延迟 λ 调优专门对 SafeDSR 有利。第四，评估指标（训练期累积计数）本质上是样本效率度量，用它比较 off-policy 值方法与 11 个 on-policy 策略梯度方法并不公平，且指标与回合长度存在乘性耦合；全文**没有任何最终策略的确定性评估**，这对安全类论文是严重的协议缺口。此外还存在折扣口径不一致（式(1) 用折扣成本，式(16)、式(17) 用未折扣回合成本）、J 恒为 1 因而多约束机制从未被实际验证、五项 DSR 改动无一被消融、主图无置信区间、三处叙述性结论无任何数字支撑等问题。

可复现性评级：**中等**。代码公开、环境动力学在正文中给出完整解析式、基线来源明确，这些都是加分项；但全部超参数在未提供的 B 节、环境布局在未提供的 D 节、硬件与运行时间全文未提及、无种子值、无调参协议。要完整复现，最需要补齐的是 5.4 节及其协议、B 节超参表、D 节布局配置，以及一个在冻结特征张成空间之外的成本迁移实验。
